# Footprint / Numbers Bars 设计

[文档导航](../README.md) · [行情投影架构](../architecture/engine/market-data.md) · [成交构柱 API](../api/aggregation.md)

本文档是 GitHub issue #23 的长期设计契约。它描述了 Aeris Charts 用于专业足迹图系列的 tick 真值（tick-truth）模型。[架构总览](../Architecture.md)及其主题文档仍是 crate 归属与依赖方向的权威依据。

## 1. 成交事件与排序模型

足迹图系列摄入的是成交，绝不是合成的 OHLC 聚簇。每个事件携带：

- 带符号的 Unix 时间戳，微秒精度；
- 与 tick 对齐的价格和正的成交量；
- 宿主提供的主动方（`buy`、`sell` 或 `unknown`）；
- 可选的同时刻买价（bid）和卖价（ask）；
- 可选的提供方序列号和稳定的成交 ID；
- 为日后的微观结构扩展保留的不透明条件位；以及
- 可选的宿主自定义交易时段 ID。

微秒既保留了交易所的排序，又使当代日期能在 JavaScript 数字中被精确表示。浏览器边界拒绝不安全整数。时间戳相同的事件先按提供方序列号排序，再按稳定的输入顺序排序。成交 ID 使回放具有幂等性，并允许提供方的更正替换先前的事件。同一批量中若两次出现同一成交 ID，则整体原子地拒绝，而不是选择一个未文档化的胜出者。

保留的原始成交带是权威来源。由它派生的柱可以被丢弃并重建；被封存的历史柱（见 §5）已经释放了原始成交，是最终历史。末端事件走增量路径。迟到事件或更正就地合并进规范成交带：只有从批量触及的最早规范位置起的尾部被重新排序和重新索引，派生柱从该位置之前最近的回放检查点重建恰好一次，结果与完整重建相同，并通过工作统计报告重放的成交数。它绝不会在修补柱最终合计的同时让 Max/Min Delta 路径保持过期。排序早于原始成交带起点的迟到成交或更正会改写最终历史，因此不被应用，并计入 `skipped_sealed_trades`。

价格必须落在配置的整数 tick 网格上。Aeris 拒绝离网数据，而不是悄悄舍入金融真值。成交量是有限的正数。交易时段 ID 变化会关闭当前柱，并重置交易时段累计 delta。

## 2. 主动方分类

分类是确定性的，并按权威性排序：

1. 宿主提供的 `buy` 或 `sell` 方向被视为权威。
2. 对于 `unknown`，成交价大于或等于所提供的卖价（ask）则为买；小于或等于所提供的买价（bid）则为卖。
3. 否则按 tick 规则与前一笔规范成交比较：更高为买，更低为卖，价格不变则沿用前一次已分类的方向。
4. 如果以上规则都无法判定该事件，则其保持 unknown。

未知方向的成交量计入价位、柱和 POC 的总成交量，但不计入 bid 量、ask 量、delta、失衡或累计 delta。Aeris 绝不会仅为了让聚簇看起来完整而猜测方向。历史重建按规范事件顺序重新运行分类，因此插入一个迟到事件可以正确地改变其后含糊事件的分类。

## 3. 聚合与记账

聚合模型支持对齐的时间柱、固定成交笔数柱、整笔成交的成交量柱，以及 tick 网格范围柱。成交绝不会被拆分以恰好达到成交量或范围阈值。新的交易时段总是开启新柱。时间柱按配置的锚点对齐；一旦宿主把数据流锚定到交易所交易时段窗口，则在图表的交易所时间下于每个窗口开盘时重新开始，窗口外的成交要么并入其交易日最近的柱，要么被排除（参见 [Tick 转 K 线](../api/aggregation.md#tick-转-k-线)）。时间柱保留其整秒的显示投影；成交笔数柱、成交量柱和范围柱通过图表本地的逻辑行键和引擎拥有的序列 sidecar 集成到图表中。该 sidecar 携带每根柱完整分辨率的开盘/收盘微秒边界，用于标签、十字光标和可见范围查找，因此同一秒内的多根柱绝不会被赋予虚假的时间戳。`BarSequenceMapping` 在序列被前置追加或重建时提供确定性的锚点重新定基。当图表中最后一个非时间足迹图及其依赖项都被移除时，图表会撤销该 sidecar，因此之后的纯时间系列不会继承过期的逻辑标签。非时间柱的末端更新只替换受影响的后缀，并使派生的 delta 研究保持在相同的逻辑行键上，包括设有上限的系列：保留策略从前端丢弃行键而不重新分配键，因此之后的末端更新、研究和大单订单继续从投影中第一个保留的键开始，而在修剪之后绑定的足迹图、K 线/柱或研究也从同一个键开始安装。大单订单同样使用其开仓柱的逻辑行键，而其订单分组窗口保留微秒级的比较精度。图表值快照和系列查询暴露对应的 UTC 秒级标签，而不是内部行键。增量回放与 release 性能证据仍属于 B5 的性能退出条件。

每根柱保留 OHLC、bid/ask/unknown/总成交量、成交笔数、最终 delta、delta 百分比、交易时段累计 delta 以及已排序的价位。每个价位保留 bid、ask、unknown、总量和 delta。成交按品种的 `tick_size` 校验。存储的价位按品种 tick 保存，整数价位标识为 `round(price / tick_size)`，以避免重复的浮点价格比较。`ticks_per_row`（默认 1）只在呈现时把相邻 tick 归并为一行，使密集品种保持可读：呈现的柱（`FootprintAggregator::presented_bar`、`ChartEngine::footprint_bars` 与 `footprint_bar`）的行标识为 `floor(round(price / tick_size) / ticks_per_row)`，价位的 `price` 是其所在行的最低 tick，失衡、堆叠与 POC 在合并后的行上重新计算，而柱的 OHLC 保留精确的成交价。因此更改行或失衡规则只就地重新派生显示状态，不重放任何成交，封存历史也随之保留。

运行中的柱 delta 从零开始。每笔被分类为买的成交加上其成交量，每笔被分类为卖的成交减去其成交量。Max Delta 是每个事件之后观测到的最高运行值（包括初始的零）；Min Delta 是最低值。它们在实时聚合期间被保留，并在历史变更之后从成交带重新计算。最终 delta 不用于近似任一极值。

POC 是总成交量最大的价位。并列时，选择最接近柱收盘价的价位，其次选择较低的价位。该规则在实时构建和历史构建中都是稳定的。

专业的对角失衡规则比较：

- 价位 `p` 的 ask 对比 `p - 1 tick` 的 bid；以及
- 价位 `p` 的 bid 对比 `p + 1 tick` 的 ask。

占优的一方必须达到配置的最小成交量和配置的比例。只要满足最小成交量，对侧成交量为零即符合条件。缺失的中间价位会打断堆叠。长度至少为 `consecutive_levels` 的相邻连续段中，每个成员都被标记为堆叠 bid 或 ask 失衡。水平失衡和其他失衡模式仅是视觉投影；它们不能改变所存储的 bid/ask 真值。

视觉聚合模式独立于柱的构建：宿主可以基于同一份数据请求 Bid × Ask、Total、Delta、柱内分布（profile-in-bar）、成交量价位梯（volume-ladder）、水平失衡（horizontal-imbalance）或 bid/ask 直方图（bid/ask-histogram）单元格，而无需重建成交带。

### 共享图表成交带与派生研究

`ChartEngine::add_trade_stream` 创建一个以宿主品种标识为键的有界流。该流拥有分类、规范排序、更正、保留策略和单调递增的修订号；足迹图、CVD、delta 直方图和大单指标绑定到该标识，而不是再保留第二份提供方事件成交带。CVD 支持交易时段、连续和锚定三种重置。保留策略绝不会改写保留柱的 CVD 值：该流把被淘汰柱的交易时段累计 delta 和连续累计 delta 作为种子携带，而锚定 CVD 保留其被淘汰柱所建立的基值（在锚点柱被淘汰之后才创建的 CVD 锚定在第一根保留的柱上）。Delta 依赖项从同一批柱读取最终 delta、Max/Min Delta、delta 百分比和 bid/ask/unknown 成交量，而成交量依赖项为普通的由 tick 构建的 K 线读取每根柱的总成交量。

流是其依赖项的唯一写入者。与足迹图一样，绑定成交的 K 线或柱，以及 CVD、delta 和成交量研究，都拒绝一切宿主数据写入（set、install、update、batch、merge、带序列的更新、逐点颜色、pop），因此误写不会再改写非时间流的其他所有呈现所沿用的行键。一个系列只有一个引擎写入者：对于已被流、研究、重采样器或合成柱写入的系列，`configure_footprint_series` 返回 `FootprintError::SeriesOwned`；对于已被重采样器、合成柱或转换为 K 线的研究所写入的 K 线或柱，`bind_trade_bar_series_to_stream` 同样返回该错误（足迹图或标量研究会先因 K 线类型检查失败而返回 `UnsupportedTradeBarSeries`；已绑定的 K 线可以自由地重新绑定到另一个流）。重采样和合成柱配置拒绝把这样的系列作为目标。末端更新和重建路径通过引擎内部的安装器写入，而不是宿主入口，因此该守卫不会给末端更新增加任何开销。保留策略仍跟随该流：已绑定的 K 线拒绝 `max_points` 上限，而研究保留其自身的上限。

大单（`ChartEngine::add_big_trades`，`big_trades.rs`）是叠加在任意 K 线、OHLC 柱、折线、面积、基线或足迹图系列上的独立指标。交易所会把一笔主动订单报告为多笔成交，因此该指标先重建订单：同一已分类主动方、同一交易时段、与前一笔成交间隔不超过分组窗口（默认 1 ms），且价格从不逆主动方移动的连续成交构成一个订单；无法分类主动方的成交不会开启订单。过滤作用于重建出的订单，因此以许多小笔成交完成的大单仍然合格。自动过滤器保留严格大于最近 4,096 个已完成订单的弱（95）、中（98）或强（99.5）分位数的订单，每 128 个订单刷新一次阈值，因此在前 128 个订单完成之前不显示任何气泡；固定过滤器保留不小于最小成交量的订单。每个订单在其成交量加权均价处绘制一个半透明、带买卖方向描边的圆，面积与保留订单中最大成交量之比成正比，按从大到小绘制以使较小的订单保持可读；跨越多个价位的扫单另绘一条细的区间竖线，容得下的气泡内显示紧凑的成交量（`250`、`1.2k`）。气泡是绘制在所有系列之上的窗格 chrome。最多保留最新的 4,096 个合格订单。

订单归属于其开仓的那根柱：在时间柱上，订单携带其首笔成交所在柱的开盘时间，因此即使交易时段锚定把集合竞价或午间成交并入该柱，订单仍绘制在该柱上；被交易时段策略排除的成交既不开启也不延续任何订单。在非时间柱上，订单携带其开仓柱的行键，保留策略不会重新编号它；流没有任何展示时，行键是流内的柱位置，保留策略会把它们随柱一起平移。末端追加只用新成交延续仍在形成的订单；更正、迟到事件与回放定位从回放起始状态对原始成交带回放一次。封存柱释放成交之前，大单先把这些成交折叠进该起始状态，因此封存历史中的气泡、自动过滤器的样本与阈值以及仍在形成的订单都在回放中保留，两条路径的结果完全一致。成交带替换、交易时段或网格变更以及过滤或分组设置的变更从空状态回放原始成交带，封存历史的气泡不再保留。保留策略就地丢弃开仓于被淘汰柱的订单（在回放起始状态中同样如此），并保留其余订单与自动过滤器的状态，因此保留的气泡恰好等于不设保留上限的图表在保留柱上的气泡，淘汰历史不会回放成交带。前置到封存历史的回补页单独重建其订单，并把它们加在封存历史之前；跨越衔接处的订单在该处拆开。迟到事件在一次从最近检查点起的规范重建之后，从第一根重建柱起刷新所有依赖项；流遥测报告修订号、保留容量、依赖项数量（大单指标计入其中）、依赖项重建次数和增量更新次数，以及生命周期累计的工作计数器：已计算的研究行数、已投影的柱行数、大单已扫描的成交数（`big_trades_prints_scanned`）和大单回放次数（`big_trades_replays`）。

## 4. 渲染与细节层级（LOD）

足迹图几何在 `aeris_charts_engine` 中构建为普通的、与后端无关的图元。后端保留所得的顺序、裁剪、alpha、文本对齐和像素坐标；没有任何执行器会重新计算 POC、delta 或失衡。

每根可见柱占其柱槽 90% 宽的一个聚簇，其余部分把相邻柱隔开。在可读密度下，每根可见柱依次绘制：

1. 聚簇左缘一条 2 px 的成交区间线，颜色跟随柱的方向（收盘不低于开盘用 ask 色，否则用 bid 色）；
2. 每个显示行的 bid × ask 单元格（或所选的 Total/Delta 等布局）：每一半带一条淡色的侧轨、一根从中线向外生长的成交量柱和其数字，失衡与堆叠失衡的一半改用失衡色并以粗体显示数字；
3. POC 行的轮廓：一个透明填充、带 POC 色边框的圆角矩形，不遮挡数字；以及
4. 有界的两行柱摘要：`Δ` 最终 delta（按正负着色）与 `V` 总成交量，位于柱最低行之下，放不下时省略。

文本使用图表已解析的字体族、居中的列和配置的字号；放大缩放时文字不会随行变高而变大。紧凑成交量对小于 0.01 的成交量保留两位有效数字，因此有成交的价位绝不显示为 `0.00`。颜色在帧执行之前解析，默认文本颜色跟随实时的图表主题变更。即使 LOD 隐藏了文本，Max/Min Delta 仍然可以查询。

自动行（`adaptive_rows`，订单流呈现在 `ticks_per_row == 0` 时启用）为每一帧选择一个合并系数：存储行在当前比例尺上的高度不足以容纳文字（详细层级为字号加 5 px，单元格层级为 3 px）时，按 1-2-5 步长（`footprint_row_merge`，上限 10⁹）把相邻行合并为显示行，并在合并后的行上重新计算失衡、堆叠与 POC，使每个强调都描述实际绘制的内容。同一帧内所有可见柱使用同一个系数，因此行在柱之间保持对齐。

LOD 依据水平方向的柱宽和垂直方向的显示行高选择：

- **详细（Detailed）：** 柱间距至少 48 CSS px 且显示行高至少为字号加 3 px 时，绘制单元格、数字、POC 轮廓、失衡与摘要。`FOOTPRINT_BAR_SPACING`（104 CSS px）是 `fit_footprint_viewport` 打开的、在默认字号下容得下 `bid x ask` 数字的柱间距。
- **单元格（Cells）：** 柱间距至少 8 CSS px 且显示行至少 2 个设备像素时，绘制区间线、彩色的价位单元格、POC 轮廓和堆叠强调，不绘制字形。
- **摘要（Summary）：** 每根柱一个按 delta 着色的区间柱体加一条 POC 标记。帧工作量以可见逻辑范围为界；被隐藏的文本不会进入绘制列表或文本图集。因此每个后端接收到的 LOD 选择完全相同。

几何把第 `i` 个绘图行映射到流的第 `i` 根可见柱；按键裁剪的保留策略、回放截止与封存都保持这一对齐。

## 5. 存储、失效与恢复

一个图表级的流拥有一份规范成交带和一个派生柱向量。足迹图系列只拥有视觉选项和一个流句柄；CVD、delta、成交量和大单依赖项不拥有提供方成交带。一根柱拥有已排序的价位；不存在渲染器侧的聚簇缓存。末端追加只修改活跃柱或追加一根柱，只把变化的后缀投影到足迹图和任何已绑定的 K 线/柱（在保留上限下同样如此），并使这些系列失效。CVD/delta/成交量研究只重新计算该后缀（CVD 从缓存的累计折叠状态继续），大单只用新追加的成交延续仍在形成的订单（没有大单依赖项时不做任何工作），气泡尺寸在帧构建时计算。`trade_stream_stats` 把每一项作为工作计数器报告，并且每次末端更新的结果都等于对该依赖项做一次干净重建的结果。跨过保留上限的末端更新（每经过一个滞后余量触发一次，余量为上限的 1/32）先封存最前面的柱，释放它们所聚合的恰好那些成交，再原地淘汰这些封存柱以及开仓于其中的大单订单：它不重建也不回放任何内容，也从不扫描保留的成交带，因此其工作量与被淘汰的成交加上保留的行数成正比（对保留的柱重新编号，以及数据层自身对受影响行的修剪）。该流的所有呈现都在一次事务中离开数据层：时间戳并集只合并一次，每个 plot 只重新索引一次，无论该流有多少种呈现。已关闭的柱在实时路径上是不可变的。历史插入/更正就地合并，从之前最近的检查点重建一次，足迹图投影先从第一根重建柱起推进，其余依赖项沿用逐出调整后的索引；修正使柱数减少时重新投射全部。

向量、成交带双端队列和成交 ID 索引复用其已分配的容量。柱分为两层：前导的封存柱是已释放原始成交的最终历史，其后的柱由保留的原始成交带派生并可从中重建。系列保留策略先封存、再淘汰完整的旧柱，与它们所聚合的成交一并离开（按柱计数，因此与下一根柱的开盘共享同一微秒的成交仍留在其自身的柱中；交易时段锚定柱中被并入的开盘集合竞价成交，其时间戳早于该柱的开盘，随该柱一起被淘汰；被交易时段策略排除的成交不属于任何柱，因此淘汰会跳过它们，并只带走时间戳早于第一根保留柱首笔成交的那些成交），同时保留其余成交带所需的分类/交易时段种子，并在淘汰时把被淘汰柱的 delta 计入连续累计 delta 种子；不会残留孤立的成交带或派生历史。ID 索引保存成交带的绝对位置，因此封存只移除被释放的 ID 并推进绝对基址，保留后缀内的回放检查点被重新寻址而不是重建。绑定到该流的每个足迹图都丢弃相同的行，因为足迹图几何对第 `i` 行读取流的第 `i` 根柱。大单回放只保留最新的 4,096 个合格订单，因此对长成交带回放时的容量与成交带长度无关。订单流呈现的原始成交带另以 `ORDER_FLOW_MAX_RETAINED_TRADES`（262,144 笔）为上限：追加的宿主后缀在成交带上累积，使足迹柱比宿主更短的滑动成交窗口存活得更久，超出上限时按同一滞回余量封存完整的最旧柱（正在形成的柱从不封存）。封存不改变任何柱，因此封存的足迹柱、其研究行与大单气泡都作为历史保留。封存历史最多跨 `ORDER_FLOW_MAX_RETAINED_SESSIONS`（5）个交易时段，整个流最多占用 `ORDER_FLOW_MAX_STREAM_BYTES`（384 MiB），超出时经同一条淘汰路径从前端淘汰最旧的封存柱；回放时钟隐藏部分历史时不淘汰。被交易时段策略排除、不属于任何柱的成交全部计入原始成交带预算，因此位于原始柱之前与之间的被排除成交不会让成交带超过上限（代价是当这些成交位于被封存柱之前时，最多多封存与其数量相当的柱）；位于最新柱之后的被排除成交（已收盘交易时段的尾部，或没有任何柱的成交带）无法随前端柱封存离开，会保留到下一根柱开启。

订单流呈现从不隐藏主系列：显示足迹图的宿主把主系列安装为空白数据（只有时间），它只提供柱网格与时间轴；足迹图系列拥有自动缩放、最新值标签、价格线与倒计时，成交带未覆盖的柱保持空白而不是回退为 OHLC。`histogram_updown` 成交量直方图在主系列该行为空白数据时，从同一窗格中可见的足迹图读取方向，并使用该成交量系列自己的 `histogram_updown_rule`；没有足迹柱覆盖的槽位保持系列的纯色。未给出 `primary_values_series` 时，金融图例的主行同样读取订单流呈现的足迹图。

更早的历史通过 `prepend_order_flow_history` 补回：宿主从最旧的保留成交向后分页，晚于或等于历史起点的成交和重复的成交 ID 被跳过。没有封存柱时该页并入原始成交带并精确重建；已有封存历史时，该页在流自身的交易时段网格上单独聚合，成为新的封存历史：与旧前端共享开盘时间的边界时间柱被精确合并，该页收盘时的交易时段 delta 延续到同一交易时段的前导柱，主动方未知、位于旧前端的成交保留已有的分类。一旦有柱因预算被淘汰，更早的页即被拒绝，并以 `history_full` 告知宿主停止分页。会在同一开盘时间打开两根时间柱的页在任何改变之前被拒绝（`ProjectionTimeCollision`）。`replace_order_flow_window` 安装宿主改写后的有界窗口：窗口只对其最早成交及之后的区间具有权威性，因此更正、撤销、回补成交和重新开始的成交带生效，而更早的柱（包括封存历史）保持不变；窗口移除了柱时，每个依赖项随之缩短。交易时段、交易所时间、周期或 tick 大小在历史封存之后改变时，引擎丢弃封存柱并在新网格上重新聚合原始成交带，历史起点随之移到原始成交带起点，宿主经同一个 `prepend_order_flow_history` 路径在新网格上补回历史，非时间柱上与原始成交带首笔同一微秒的被释放成交，若按序列号排在旧前端之前或携带成交 ID，也一并补回，即使补回到达之前实时追加已再次封存柱；与旧前端时间和序列号都相同且没有成交 ID 的成交无法去重，因此被跳过（详见[行情投影架构](../architecture/engine/market-data.md#共享成交流与唯一写入者)）。引擎内存遥测包括成交带、价位、封存历史、ID 索引、大单订单和保留容量。

设备丢失与该模型无关：无头的成交带和派生柱保持完好，而浏览器执行器回退。渲染器缓存由同一帧契约重建。

## 6. API 接口面

Rust 引擎拥有以下类型化命令：创建/配置足迹图系列、原子地替换成交带、追加/更正单笔成交、摄入有序批量、查询柱和价位，以及读取工作量/内存统计。WebAssembly 边界接受用于历史和实时批量摄入的类型化列；对象转换仅保留给低频的单事件 API。

TypeScript 包通过 `chart.add_series("footprint", options)` 暴露专用的 `footprint_series_api`。其输入是 `footprint_trade`，而不是 `series_data`；通用 OHLC `set_data` 对该类型被拒绝。查询暴露柱 OHLC、价位、POC、最终/Max/Min Delta、delta 百分比、bid/ask/unknown/总成交量、交易时段 delta 和堆叠标志。图表级方法创建 CVD 和 delta 依赖项；`add_big_trades` 返回一个 `big_trades_api` 句柄，用于读写选项、读取快照与移除；流方法查询修订号/遥测。数据变更通知对替换/历史重建使用 `full`，对真正的末端更新使用 `update`。

选项涵盖 tick 大小、每行 tick 数、时间柱间隔/锚点或成交笔数/成交量/范围构建方式、失衡比例/最小值/连续个数、视觉单元格模式、自动行（`adaptive_rows`）、颜色、文本大小、摘要，以及通用系列保留策略。更改每行 tick 数或失衡规则只就地重新派生显示行与失衡标志，不重放成交，封存历史随之保留。更改 tick 大小或柱聚合会从成交带原子地重建，同时保留回放时钟所隐藏的成交、保留种子和交易时段锚定，并丢弃无法重新放置的封存历史；已绑定的 K 线/柱随之更新。仅视觉相关的选项只使系列帧层失效。

Rust 宿主通过订单流呈现接入：`add_order_flow_presentation` 一次安装整张图（`ticks_per_row == 0` 选择自动行），`update_order_flow_presentation` 替换或追加成交带，`replace_order_flow_window` 安装改写后的窗口，`prepend_order_flow_history` 补回更早的历史并返回 `HistoryPrefixStats`，`reconfigure_order_flow_presentation` 就地改变行、失衡、单元格显示、所显示的系列与大单指标（只有不同的 tick 大小或柱聚合需要新的呈现），`fit_footprint_viewport` 在用户进入足迹图模式时打开聚簇缩放，`remove_order_flow_presentation` 拆除整张图。`ChartEngine::trade_stream` 只读暴露流的原始成交带、柱与保留的历史（`sealed_bar_count`、`history_start_micros`、`accepts_older_history`）。浏览器包暴露足迹图系列选项中的 `adaptive_rows`；上述订单流呈现方法目前只在 Rust 侧提供。

宿主回调仅通过普通的图表查询/事件路径接收派生快照。Aeris Terminal 和其他宿主仍是行情订阅、交易所日历以及选择交易时段 ID 的权威；这些关注点都不会进入渲染器。

## 7. 验证与性能证据

### 参考夹具与发布基线

密集订单流参考视图是确定性的：20 根一分钟柱，每根柱 11 个价位，tick 大小为 0.25，且每个价位都有成对的买/卖成交。它被 GPUI `plan_bench` 夹具用于 1600×900 CSS 像素、DPR 1.5、72 px 柱间距的场景，其中详细 LOD 必须输出单元格文本 run。WebGPU `perf_gate` Target J 使用同一帧契约，并为每个文本图元提供已解析的图集 quad，同时守护 2 ms 的 p99 CPU 侧编码预算；这衡量的是调度和上传准备，而不是设备呈现（present）时间。

持续的原生 release 基线仍是 Target D：保留 2,500 根一分钟柱、每根柱 100 笔成交，外加 100 根柱的实时批量和 10 根柱的更正批量。其预算为：历史加载 300 ms，实时批量 50 ms，更正 300 ms，帧构建 16.67 ms，且保留量以配置的历史长度为界。随后它把 9,000 次单笔成交的实时末端更新（跨过保留上限一次）流入带有已绑定 K 线、CVD、delta 和大单的图表，要求每次末端更新的工作计数器都保持在变化的柱后缀和新成交之内、大单不发生回放、不发生成交带重建，把末端更新的 p99 预算定为 0.25 ms，并把最慢的末端更新（即跨过上限的那一次）的预算定为一个 16.67 ms 帧。触发修剪的末端更新还会对整个数据层恰好运行一次并集合并和一次重新索引，`perf_gate` 要求其与工作计数器一并满足。Target R 与 Target S 覆盖订单流呈现：持续的实时成交带跨过原始成交带上限并注入一笔迟到成交，以及七个交易时段的历史经过封存与交易时段淘汰，预算见[性能契约](../development/performance.md#订单流性能目标)。命令和阈值保存在 release 示例中，因此可以对干净的 `--release` 运行进行比较，而无需把特定机器的计时数据引入仓库；`perf_gate` 会对照这些预算打印测得的末端更新 p99 和最慢的末端更新。其仅作报告的 Target D2 会打印数据层的保留修剪在不同系列数（1、4、8）和保留行数（2,500 到 40,000）下的耗时，对每个系列各做一次 `trim_fronts` 对比一次 `trim_front`，因为修剪成本同时随二者增长。它没有阈值：修剪保持与保留行数成正比，而与上限无关的成本（汇总金字塔和 plot 索引中的绝对行标识，以及系列列上的惰性头部偏移）则被推迟，待产品就修剪延迟是否必须不随上限增长作出决定；其度量是 Target D2 在 28,800 行和四个或更多系列下，对照约 2 ms 的标准。

有限帧数的 GPUI 真实窗口探针也已在当前 Windows 显示器上用足迹图夹具运行：在 DPR 1.25 和 500 根源柱下的 30 帧产生了 24 个缓存的文本 run（零次未命中），适配器 p50/p99 为 2.005/4.508 ms，GPUI 绘制 p50/p95/p99 为 2.005/2.369/4.341 ms。这些数字是一次被观测的宿主运行结果，不是可移植的 release 预算；该探针不暴露原生 WebGPU 设备呈现计时。

2026-09-26 的 release 门禁通过原生 WebGPU CPU 侧编码路径测量了同一密集夹具：120 个已解析的文本图元产生 120 个图集实例，p99 编码样本为 0.00 ms，对照 2.00 ms 的 Target J 预算。Chromium 足迹图套件也通过了全部六个用例，包括 WebGPU 共享帧路径。这些检查覆盖执行器调度和浏览器集成；原生设备呈现计时以及上文各 GPUI 显示器相关数字仍属诊断性质，而非可移植预算。

订单流里程碑证据采集于 2026-09-26。GPUI 窗格截图在 DPR 1.25 下使用 `AERIS_CHARTS_GPUI_FEATURE=footprint`，为密集的 12 根柱夹具生成了一张 1543×873 的图像；该图像经目视检查，单元格文本可读、列对齐稳定、窗格内容未被裁剪。浏览器无障碍审查通过了聚焦的 `unified-interaction-accessibility.spec.mjs` 契约：一个有界的应用表面、隐藏的 canvas 像素、流式更新期间静默的 live region，以及可回滚的键盘绘图编辑。该截图仍是临时的里程碑产物；命令和元数据记录在此，因此无需向仓库添加二进制夹具即可复现该证据。

确定性的合成成交带覆盖：网格边界、未知方向处理、报价/tick 规则分类、相同的时间戳和序列、迟到事件、更正、交易时段重置、贯穿实时末端更新和保留策略的交易时段锚定时间柱、所有柱模式、bid/ask/总量/delta 价位、POC 并列、均值回归的 Max/Min Delta 路径、失衡的两侧，以及堆叠连续段的中断。帧测试覆盖每一种已交付的 LOD 和图元顺序。浏览器测试通过 Canvas2D 和 WebGPU 执行同一份由引擎构建的帧，以及类型化摄入和公共查询；GPUI 和原生消费这些已有的、与后端无关的图元种类，不含足迹图数学运算，也没有足迹图专用的执行器分支。

release 证据夹具测量一份大型历史成交带加上持续的实时追加。它记录聚合/重建工作量、帧 CPU、绘制次数、上传字节数、保留内存和分配。验收要求末端更新不重建先前的柱、在配置的保留策略下内存稳定，并且随着历史增长可见帧的工作量保持有界。
