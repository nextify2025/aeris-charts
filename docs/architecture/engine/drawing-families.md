## 目录与共享钩子

B8 目录即 AerisTerminal 上游的目录：85 个种类，wire id 为 `0..=84`，按上游的枚举顺序排列（从趋势线到锚定 VWAP，接着是价格范围、日期范围与日期价格范围，然后从射线到柱形态），列于 `DRAWING_TOOL_SPECS`（`drawings/tools.rs`）中。每个种类恰好有一个渲染器，由其规格的 `family` 决定是哪一个。除三个测量工具外，每个上游种类都是 `family: None`，对这些种类而言，上游的实现是唯一的实现：目录规格、`drawings/geometry.rs` 中的主体解析器（`DrawingBodyGeometry`）、`frame/drawings.rs` 中的转换分支，以及对同一已解析主体的精确命中测试，详见[绘图几何](drawings.md#派生运行时与几何)。恰好有十个种类设置 `family: Some(..)` 并使用下文的族路径：上游没有的七个自有线工具（`horizontal_segment` 240、`vertical_ray` 241、`vertical_segment` 242、`price_line` 243、`price_channel` 244、`simple_tag` 245 与 `simple_annotation` 246），以及测量工具 `price_range` 13、`date_range` 14 与 `date_price_range` 15，它们保留自有线的实现（价格 tick 吸附、统计、坐标轴标签以及 Shift 点击快速测量；见[测量工具](drawings.md#测量工具与瞬态测量)）。两条线都实现过的工具，其自有线族渲染器已在两条线合并时退役：上游转换所不具备的渲染器附加功能列在 `drawings/tools.rs` 顶部的 `ponytail:` 注记中，其选项键仍会被存储但不起作用（见[族选项](#族选项)）。自有线写出的文档（以及能证明其出处的剪贴板与同步条目）在恢复时会携带这些附加功能的自有线默认值（见[旧版工具名与文档迁移](#旧版工具名与文档迁移)），因此每一项在上游的转换之上重新实现后，这些文档即恢复自有线的外观，而新绘图保持上游的外观；按维护者的决定不予恢复的项（会改变上游锚点或选项契约的项），以及按决定保持上游画法的其余渲染差异，也在该注记中逐一列出，后者另见[持久化 V1](../../api/compatibility.md#持久化-v1)。其中下列各项改为在上游的转换之上重新实现：线条工具的统计框、角度线的参考线与圆弧以及线段工具的端帽规则由存储的 `tool_options.line` 块选择，叠加在上游的线段与十字线分支之上，射线按 `extend_left` 向后延伸，信息线、角度线与箭头线的竖直线段按 `extend_*` 延伸（见[线条](#线条)）；通道的呈现由存储的 `tool_options.channel` 块选择，叠加在上游的通道与回归分支之上：平行、平顶、平底与不相交通道的虚线中线，回归趋势线以 `middle_color` 绘制的虚线中心线、逐侧偏差覆盖与开关、OHLC 源以及皮尔逊 R；按维护者的决定改变上游行为的有：通道的一次带状填充在按方向配对的两条线之间进行，因此第二条线反向的不相交通道填满整个四边形，相交的两条线（包括水平线穿过基线的自有线 `flat_top_bottom` 转换得到的不相交通道）填充在交点处相接的两瓣，绘制与选中时的填充命中一致（C3），回归趋势线只沿时间移动（C1，其手柄位于拟合线两端，现由上游的手柄投影给出），回归趋势线按 `extend_*` 延伸，其区带在选中时是拖动面（T1）（见[通道](#通道)）；斐波那契工具的呈现由存储的 `tool_options.fibonacci` 块选择，叠加在上游的斐波那契、时间档位与斐波那契弧分支之上：趋势线、速度扇形的网格、完整的速度弧圆、垂直标签对齐，以及环形工具在窗格可见部分内的 0.1 px 精确圆环，没有档位的螺旋线绘制黄金螺旋，每个档位分支的档位标签以及选中时的区带是主体命中目标（包括江恩扇形的区带），斐波那契通道按 `extend_*` 延伸（见[斐波那契](#斐波那契)）；叉形线与江恩工具读取存储的 `tool_options.gann` 块，叠加在上游的叉形线、江恩网格与斐波那契分支之上：选中的叉形线与叉形扇的区带以及江恩网格在框外绘制的档位单元格是拖动面，叉形线与叉形扇的叉柄中点手柄，江恩框独立的时间档位（重叠的逐轴区带，决策 G1）与角度线，江恩方图的统计框（新方图默认关闭，自有线文档开启，决策 G2），江恩扇形与固定方图的 `scale_ratio`，固定方图位于绘制出的对角上的手柄，以及价格基准缩放对 `scale_ratio` 的同步缩放（见[叉形线与江恩](#叉形线与江恩)）；形态与艾略特波浪在上游的折线分支之上叠加共享部件：谐波形态的虚线比率连线与带框比率（`tool_options.pattern.show_ratios`，存储的默认值为开启，决策 P6），XABCD 与 cypher 在 `fill_enabled` 时着色的三角形，三角形形态按 `extend_left`/`extend_right` 绘制到顶点的两边（决策 P3），顶点标签是主体命中目标（保留上游的位置，决策 P1），`show_wave: false` 只保留艾略特标签；按维护者的决定改变上游行为的有：每个头肩形态都绘制颈线（P2），艾略特波浪按其级别的 Frost–Prechter 记法标注且起点不标注（P4），形态与艾略特波浪放置时从第二个锚点起预览标签、比率与填充（P5）（见[形态与艾略特波浪](#形态与艾略特波浪)）；通道的 `extend_left` 与 `extend_right` 会把两条线及其填充一直延伸到窗格边缘（`geometry.rs` 中的 `extend_channel_line`）；标注框在其尖端与框上各保留一个手柄（`CALLOUT` 设置 `DrawingHandleMode::Anchors`）；实线荧光笔转换为其展开路径周围管状区域的一次半透明 `BandFill`（`shape::tube_ribbon`），因此自身重叠的描边在 GPU 执行器上与在 Canvas2D 上一样，每个像素只混合一次（虚线荧光笔保留描边）；没有拟合结果的回归趋势线会绘制其锚点之间的虚线段（`RegressionWindow`，见[系列数据读取方](#系列数据读取方)）；椭圆、圆、圆弧、曲线与双曲线的曲线按感知裁剪的方式展平（见[绘图几何](drawings.md#派生运行时与几何)）；形状在上游的圆弧、曲线、折线、旋转矩形与三角形分支之上恢复：圆弧的圆弓形与曲线的弦区按 `fill_enabled` 填充（选中时是主体命中目标），曲线按 `extend_*` 沿切线延伸，折线按 `tool_options.shape.closed` 闭合（按 `fill_enabled` 以非零规则填充，不绘制端帽；新折线保持上游不填充的默认值，自有线文档保持填充，决策 S1）；按维护者的决定改变上游行为的有：放置折线时点击第一个顶点即闭合（S2），椭圆以矩形的八个边界手柄编辑并以 Shift 拉成圆（S3），旋转矩形另有近侧宽度手柄、拖动边的角点保持宽度（S4，仅宽度手柄；位于远侧边中点的第三个手柄现由上游的手柄投影给出），圆弧、曲线与双曲线先放置两端（S5；曲线经过其锚点现已是上游的契约），圆弧与曲线按 `stroke_start`/`stroke_end` 绘制端帽（S6），旋转矩形与三角形的外框为一条无缝描边（S7）（见[形状](#形状)）。标注由存储的 `tool_options.projection_annotation` 块选择自有线外观（块存在即选择，处于默认值时写为 `{}`，决策 A1），叠加在上游的投影、便签、评论、价格便签、价格标签、路标、箭头标记与预测分支之上（便签与价格便签只在恰有一个锚点时取自有线外观）：投影的扇区（`DrawingBodyGeometry::Sector`，决策 A2）及其目标旁的统计框，便签的图钉（`NotePin`）与只在编辑、聚焦或 `always_show_text` 时显示的文本框，评论与价格标签位于锚点处的对话气泡（`SpeechTail`，决策 A5），价格便签带框的价格（只恢复这一附加部分，决策 A4），路标的文本牌，锚点重合的路标立起的自有线 40 CSS px 杆及其杆顶手柄，箭头标记位于尾部之外的文本，预测的源点、源价格框与目标框（变动、目标时间，以及按市场涨跌色显示的 `Success`/`Failure`，两框都是主体命中目标，决策 A10），以及自有线外观标注放置时的初始文本（决策 A6）；路标放置时打开的编辑器（决策 A7）已被上游取代：上游在两种外观下都打开路标编辑器；与外观无关的有：便签、评论、标注框、价格便签与锚定文本的多行文本（R9：上游外观的框在共享的 `annotation_layout` 中按行排布，锚定文本与自有线外观的框使用 `TextBlock`；无块的路标保持单行，与上游一致），源范围宽于 512 个槽位的柱形态聚合为以桶序号为偏移的 OHLC 柱（决策 A9）（见[投影与标注](#投影与标注)）。`kinds/shapes.rs` 保留其公共选项类型与自有线的旧版默认值表，另含上述形状呈现的选项读取、弦区填充规则、派生手柄及其拖动与放置转换，`kinds/fibonacci.rs` 另含上述斐波那契呈现的选项读取，`kinds/pitchforks_gann.rs` 另含上述叉形线与江恩呈现的选项读取、统计框部件、派生手柄及其拖动，`kinds/patterns_elliott_cycles.rs` 另含上述形态呈现的部件解析、顶点标签放置与艾略特记号；`kinds/lines.rs`、`kinds/channels.rs` 与 `kinds/projection_annotations.rs` 保留自有线工具与范围工具，以及下文所述的数据读取方（[系列数据读取方](#系列数据读取方)）、旧版默认值与内置图标字形（[锚定文本与图标戳](#锚定文本与图标戳)）；`kinds/projection_annotations.rs` 另含上述标注自有线外观的选择谓词、文本框与部件、派生手柄及其剔除余量。

上游的目录常量显式设置 `text_layout`。`line_spec` 与 `channel_spec` 种类（射线、延长线、信息线、角度线与箭头线；平行通道、平顶通道、平底通道与不相交通道）保持 `Segment`：标签跟随前两个锚点、随之旋转并取其描边颜色，居中标签会拆分描边。`shape_spec` 以及由它构建的每个种类（回归趋势线、从旋转矩形到双曲线、斐波那契、叉形线、形态、艾略特波浪、周期、标记、价格标签、图标戳、江恩、投影、预测与柱形态）都使用 `Box`，文本标注、折线与荧光笔同样如此，十字线则使用 `Box` 并带有水平线的 `axis_price_label` 标签。`Drawing::new` 把趋势线、标注框与价格便签（上游的规则）以及布局为 `Segment` 的族工具的标签对齐默认设为右/上；其他每个种类都从居中开始。

族路径服务于这十个族工具。每个族模块包含其工具规格、一份被这些规格引用的 `static FAMILY: DrawingFamily` 钩子表、其类型化选项块及其测试（`kinds/<family>/tests.rs`）。钩子表是封闭的编译期表，而不是插件注册表。`DrawingFamily::new` 接收两个必需的钩子 `build_parts` 与 `kind_options`，并让每个可选钩子都从一个中性默认值开始，族在其 `static` 初始化器中通过赋值覆盖它：`apply_defaults`（由 `Drawing::new` 应用的种类默认值，因此创建、模板、恢复、粘贴与 schema 默认值保持一致）、`decoration_extent`（为锚点之外的框与标签提供的保守 CSS-px 剔除余量；它是测量出的文本宽度，缓存在绘图运行时中，在绘图或选项变更时以及宿主经 `set_text_measure` 安装或清除文本测量回调时重新计算）、`extend_schema`（追加在通用描述符之后的 `tool_options.*` 描述符）、`owns_labels`（该族自行渲染通用的 `labels`）、`owns_text`（该族把通用的 `text` 布局在自己的部件中，因此通用文本遍历会跳过它）、`partial_preview`（放置预览从第二个锚点起即可解析部件），以及 `handles`。`handles` 编辑 `drawings/handles.rs` 依据规格的手柄模式以媒体像素构建的手柄集合（把某个手柄移到派生几何上，例如价格通道的第三个手柄位于其第二条线上，或删除某个手柄），而选中手柄的绘制、放置预览（仅限已放置锚点的手柄）、手柄命中测试、键盘手柄循环与拖动起始，全都读取这同一个集合。没有族的上游种类在同一位置经由 `kinds::upstream_derived_handles` 编辑该集合，其第一步是上游 `anchor_handle_points` 的投影（回归趋势线位于未延伸的拟合线两端的手柄，平行、平顶、平底通道与斐波那契通道位于第二条线上的第三个手柄，旋转矩形位于远侧边中点的深度手柄，见[绘图](drawings.md#派生运行时与几何)），其后是各种类的派生手柄（叉形线与叉形扇追加的叉柄中点手柄，以及固定江恩方形取代其第二个锚点手柄、位于绘制出的对角上的手柄，见[叉形线与江恩](#叉形线与江恩)；旋转矩形的近侧宽度手柄，见[形状](#形状)；自有线外观中锚点重合的路标位于杆顶的手柄，见[投影与标注](#投影与标注)），因此上游种类的派生手柄同样只有一个手柄集合。每个拖动采样（无论是指针拖动还是键盘微调）都会运行通用的部件拖动：锚点经数据时间吸附、磁吸、时间槽吸附与拉直后重新锚定，或本体按整柱平移（见[绘图](drawings.md#规范状态与工具目录)）。派生的 `DrawingDragPart::Handle` 走同一条拖动路径：`drawing_drag_apply` 的 `Handle` 分支把手柄从其基线媒体像素（`DrawingDrag::handle_px`，按下时由手柄集合解析，数据驱动的重新定基时重新解析）按指针位移移动，依次经规格的移动轴约束、时间吸附、磁吸与时间槽吸附（旋转矩形的宽度手柄除外），得到一个 `handles::HandleDrag` 采样（基线锚点及其媒体像素、按下时的 `tool_options`、目标点及其媒体像素、拉直与键盘步长），再由 `kinds::drag_derived_handle` 按种类解析该手柄驱动的内容：它改写锚点（经 `drawing_anchor_at`，即锚点拖动所用的同一时间吸附转换），并可返回新的 `tool_options`（固定方形的 `scale_ratio`），引擎在该采样末尾把它与锚点一并写入；种类也可整体拒绝一个采样（某个锚点无法放置，例如时间吸附后越过数据末端），此时引擎丢弃该采样的全部锚点改动，拖动保留上一个有效采样，与本体拖动一致；拖动的唯一历史条目与取消会连同锚点一起恢复按下时的 `tool_options`（`DrawingDrag::history_tool_options`），价格基准缩放也会缩放进行中拖动的这份快照。锚点拖动一侧的对应钩子是 `kinds::follow_anchor_drag`：通用锚点拖动的每个采样（指针或键盘）改写被拖动的锚点之后，它按基线锚点的媒体像素重新求出保持派生几何的其余锚点（旋转矩形转动边时保持宽度，自有线外观中锚点重合的路标的顶部随底部移动）。仅由已退役的族使用的钩子（`paint_bounds`、带 `FamilyBounds` 的 `bounds`、`reads_series_data`、`on_create`、`pane_anchored`、`reveals_on_focus`、`rescale_price_options`、`close_placement` 与 `text_box`）已连同其引擎调用点一并删除。钩子在帧构建与命中测试期间、绘图运行时缓存处于借用状态时运行，因此它们只读取引擎，绝不调用候选查询或缓存的锚点几何访问器。规格字段取代共享代码中逐种类的检查：`text_layout`、`axis_price_label`（水平线的坐标轴标签）、`axis_tag_text`（当绘图带有文本时，该标签显示该绘图的 `text` 而非价格，且该文本不会绘制在图表上，与简单标签的做法一致）、`anchor_link`（见[线条](#线条)）以及 `handles`（手柄模式；`drawings/handles.rs::drawing_handle_mode` 按绘图解析，自有线外观的便签、评论与价格便签为 `None`，自有线外观的路标为 `Anchors`）。时间槽吸附与价格 tick 吸附适用于除锚定文本外的每个工具，都不是规格字段：上游 `12035e2` 删除了 `price_tick_snap`（此前只有测量工具与仓位工具吸附价格），本仓库的 KLineChart 工具、自有线线段工具（240..=246）与三个测量工具都沿用这一条规则（见[绘图](drawings.md#规范状态与工具目录)）。

## 部件词汇与转换

一个绘图族会在调用方的空间（渲染时为位图 px，命中测试时为媒体 px）中，把一个绘图解析为 `drawings/parts.rs` 中共享的部件词汇：抗锯齿描边、清晰的整像素水平线与垂直线、成对链之间的带状填充（凸多边形通过 `fill_convex`）、圆盘，以及由同一个 `PartLabel::layout` 排版的带框文本块。派生的逻辑/价格点通过 `PartContext::point_px` 映射到该空间，该函数应用帧各自独立的水平与垂直位图比例；帧构建会以 debug 断言确认它能复现每一个锚点。帧构建在 `frame/drawings.rs` 中把部件转换为现有的 `Prim`（`build_family_prims` 经 `push_parts`；每一段描边都经过 `push_clipped_stroke`，它用 `shape::clip_polyline_to_rect` 把描边裁剪到按描边延伸量外扩后的窗格范围内，因此无论几何延伸多远，工作量与坐标都保持有界，并且和引擎拥有的所有路径描边一样，通过 `push_line_stroke` 把虚线或点线描边段拆分为实线的短划段，因为 WebGPU 细分器没有虚线概念；被裁剪的部件保留未裁剪描边段的虚线相位，因此平移时虚线绝不会偏移），而精确命中测试（`parts_hit`）检测的是同样的部件（`DrawingParts::hit`，其中虚线描边仍是一个连续的主体），所以各族工具不能分叉执行器行为，绘制出的形状与可交互的形状也不会漂移。[锚定文本与图标戳](#锚定文本与图标戳)中所述的内置图标字形回退也经由同一路径转换。

上游渲染的种类（没有族）也可以由存储的选项选择，在其上游转换分支之上叠加共享部件：帧中的 `push_parts`（`frame/drawings.rs`）在 `frame_part_context` 中解析部件，并经同一个 `push_drawing_parts` 转换（图标戳的内置字形同样经由它），命中测试中的 `parts_hit`（`drawings.rs`）以媒体 px 解析同样的部件，用 `DrawingParts::hit` 检测，标签按与绘制相同的方式测量（`measure_part_label`）。这些部件超出锚点框的范围由 `kinds::upstream_decoration_extent` 给出，与族的 `decoration_extent` 一样按文本键缓存并作为剔除余量；它们读取的 `tool_options.*` 由 `kinds::extend_upstream_schema` 列入属性 schema。两者都是 `kinds/mod.rs` 中按族分块（`// B8: <family> — begin/end`）的分派函数，第一个使用者是[线条](#线条)工具。随视口变化的装饰不能放进按选项代缓存的余量：角度线的参考线与线段的屏幕长度等长，因此 `refresh_drawing_screen_bounds` 按坐标键把屏幕框扩展到参考线的终点（`lines::angle_reference_end`，与绘制共用），语义预检则保守地把它视为从第一个锚点朝第二个锚点一侧的射线。

族工具放置期间，一旦每个锚点都已放置或处于预览中（设置 `partial_preview` 时，从第二个锚点起；形态与艾略特波浪虽没有族，也从第二个锚点起，因为它们的折线、标签与叠加部件可由任意前缀的锚点解析，决策 P5），帧的待定路径就会构建该工具自身的部件；在此之前，具有三个或更多锚点的工具会把已放置的锚点与指针连成一条以绘图描边绘制的引导折线，该折线经 `push_clipped_stroke` 转换（柱形态改为把前两个锚点围成的源窗口显示为虚线外框，与选中时相同），并在已放置的锚点上显示手柄，因此每次点击都会留下可见的笔迹。共享辅助函数位于各自的所有者处：纯几何（线段延长、中点以及到窗格的裁剪、射线裁剪、平行偏移、折线、多边形与带状命中判定，以及 `Rect` 的外扩、求交与包围盒）位于 `aeris_charts_render::shape`；线帽（`capped_segment` 就是两点的 `capped_polyline`，`cap_radius` 决定每个圆盘与箭头的尺寸）、箭头修剪、标签排版、统计框（`PartContext::stats_box` 默认以绘图描边颜色按 `STATS_ALPHA` 作底色，配以 `text_on` 选出的黑色或白色文字，线条工具的统计框使用它；`PartContext::stats_label` 使用共享的 `STATS_*` 间距与内边距，由调用方指定底色与文字颜色）以及填充约定（`PartContext::fills_hit`：区域填充仅在绘图被选中时才是主体目标，与矩形内部相同）位于 `parts.rs`；颜色解析位于契约类型上（`Drawing::stroke_color` 带规范的主色回退，以及 `Drawing::fill_or_wash`）；属性描述符构建器 `drawing_contract::descriptor`；引擎格式化的测量文本（价格经绘图比例尺的格式化器、百分比、tick 数、柱数、时间范围、时长、屏幕角度、距离）以及文本与统计字形大小（`drawing_text_size`、`drawing_stats_size`）位于 `drawings/stats.rs`；以及位于 `drawings/handles.rs` 的唯一可编辑手柄集合。

设置了 `extend_left` 或 `extend_right` 的绘图使用无界的语义边界，因此锚点滚出视野时，延长线仍保持可见且可命中；而关闭了延长的线，则与任何有限线段一样被剔除。三角形形态是例外：它的两边至多到达锚点前方一个图形宽度处的顶点，因此设置任一标志时，其逻辑边界向两侧各扩展锚点的时间跨度、价格不设边界（`patterns_elliott_cycles::extends_to_apex`），时间剔除得以保留。

## 上游种类选项

上游种类把其选项保留为 `Drawing` 上的扁平字段，由绘图补丁校验，列在属性 schema 中，会被持久化，并由模板、剪贴板与同步载荷携带：`levels` 及 `level_reverse`、`level_show_prices`、`level_show_values`、`level_show_percents`、`level_label_align`，以及（仅回撤、扩展与通道）`level_log_scale`；`gann_fans` 与 `gann_arcs`（江恩方形与固定江恩方形）；`wave_degree`（艾略特波浪）；`screen_x` 与 `screen_y`（锚定文本）；`icon_name` 与 `icon_size`（`icon_size` 用于图标戳与四个箭头标记，8 到 256 CSS px，默认 24）；`bars_pattern` 及 `bars_pattern_mirror_x`、`bars_pattern_mirror_y` 与 `bars_pattern_mode`；以及 `regression_source_id` 及 `regression_deviations`（0 到 10，默认 2）。`wave_degree` 接受上游的九个级别（从 `subminuette` 到 `grand_supercycle`，默认 `minor`），外加自有线的 `submillennium`、`millennium` 与 `supermillennium`。`bars_pattern_mode` 接受 `bars`、`oc_bars`（每根柱一根开盘-收盘竖线）以及 `line_open`、`line_high`、`line_low` 与 `line_close` 这几种线，并把 `hl_bars` 读作 `bars`。一个上限 `MAX_BARS_PATTERN_BARS` = 512（位于 `drawings.rs`，并在 crate 根再导出）限定柱形态快照的大小。`DrawingKindOptions` 把这些字段投影为 `Levels`、`GannSquare`、`RegressionTrend { source_id, deviations }`、`Elliott`、`AnchoredText`、`IconStamp`、`ArrowMarker { icon_size }`（四个箭头标记）与 `BarsPattern`；族工具则投影为 `Line`、`Channel` 与 `ProjectionAnnotation`。

## 族选项

绘图选项遵循上游的数据模型，自有线的类型化块则与之并存。`Drawing.tool_options: DrawingToolOptions` 为每个自有线族保留一个可选块，由选项 JSON、模板、剪贴板与同步载荷以及持久化放在 `tool_options` 之下携带。补丁采用深度合并（缺失的键保留其值，`null` 重置一个块），作用于一份副本，该副本经过校验并限定大小后，再一次性完成可撤销的安装。族工具读取各自的块（`tool_options.line`、`tool_options.channel`、`tool_options.projection_annotation`）。与上游扁平字段重叠的自有线键由同一个辅助函数 `drawing_contract::take_legacy_flat_options(kind, json, absent_block_is_default)` 从 JSON 中取出：它按键是否存在进行映射（只发送块中部分键的补丁，恰好只映射它发送的那些键），并让显式给出的扁平键优先；`apply_patch`（因而包括模板与粘贴）和持久化都使用它。映射如下：斐波那契块的 `reverse`、`log_scale`、`show_prices`、`show_levels`、`levels_as_percent` 与 `label_h_align` 分别变为 `level_reverse`、`level_log_scale`、`level_show_prices`、`level_show_values`、`level_show_percents` 与 `level_label_align`，其中 `reverse` 在扩展、通道与时间区上按原样映射，在回撤与速度扇形上取反（自有线的 0 层级位于它们的第二个锚点上，上游的则位于第一个锚点上），而在螺旋线（上游没有的逆时针旋转，由没有档位的螺旋线即黄金螺旋读取）以及从不读取它的工具上完全不映射，`label_h_align` 在时间区与趋势时间上互换 `left` 与 `right`（自有线以标签位于线条的哪一侧命名，上游以贴靠线条的文字边缘命名，`left` 使标签位于线条右侧）；江恩块的 `reverse`、`angles` 与 `arcs` 变为 `level_reverse`、`gann_fans` 与 `gann_arcs`（自有线文档中江恩扇形的 `reverse` 被丢弃，因为自有线的扇形从不读取它）；形态块的 `degree` 变为 `wave_degree`；标注块中柱形态的 `bars_mode`、`mirrored`、`flipped` 与 `bars` 变为 `bars_pattern_mode`、`bars_pattern_mirror_x`、`bars_pattern_mirror_y` 与 `bars_pattern`，其 `icon` 与 `icon_size` 变为 `icon_name` 与 `icon_size`（钳制到 8..256）；回归趋势线通道块中的两侧偏差及其开关不被取出：它们是 `regression_deviations` 的逐侧覆盖（缺失的一侧跟随扁平值），保留在块中，补丁不会因它们改变扁平值；自有线写出的文档还会把它们折叠进 `regression_deviations`（取已启用的较宽一侧），供读取上游契约的一方使用，其中两侧对称且均启用的区带只留下该扁平值，其余区带保留各侧（缺失的一侧写为自有线的默认值 2 或 -2）。没有扁平对应项的自有线键仍会被存储与持久化，但在其功能于上游的转换之上重新实现之前，对由上游渲染的种类不起作用：它们不列在 schema 中，也不会被渲染。已重新实现的键例外：六个上游线条工具读取 `tool_options.line`（见[线条](#线条)），其 schema 列出 `tool_options.line.stats_position`（默认值 `"end"` 是块存在时的位置；写回该默认值会创建块，`null` 移除块）；上游的平行、平顶、平底与不相交通道读取 `tool_options.channel` 的 `middle_line` 与 `middle_color`，回归趋势线读取整个 `tool_options.channel` 块（见[通道](#通道)），其 schema 列出这些键（`upper_deviation` 与 `lower_deviation` 默认为 `null`，即跟随 `regression_deviations`，取值范围 -100 到 100）；十个斐波那契工具读取 `tool_options.fibonacci`（见[斐波那契](#斐波那契)），其 schema 按工具列出 `trend_line`、`grid`、`full_circles`、`label_v_align`（`top`、`middle` 或 `bottom`，默认 `top`）与螺旋线的 `reverse`；四个谐波形态读取 `tool_options.pattern.show_ratios`，五个艾略特波浪读取 `tool_options.pattern.show_wave`（见[形态与艾略特波浪](#形态与艾略特波浪)），其 schema 各列出该键，默认均为 `true`（`show_ratios` 的默认值按决策 P6 显示比率，不是上游的外观）；折线读取 `tool_options.shape.closed`（见[形状](#形状)），其 schema 只为折线列出该键（默认 `false`）；上游的投影与标注种类读取 `tool_options.projection_annotation` 块是否存在（选择自有线外观，决策 A1）及其 `always_show_text`（自有线外观的便签在未聚焦时也显示文本框），schema 不列出它们（schema 按种类生成，列出后面板会在上游外观的绘图上写入该块并切换其外观，见[投影与标注](#投影与标注)）；江恩工具读取 `tool_options.gann`（见[叉形线与江恩](#叉形线与江恩)），其 schema 列出江恩框的 `time_levels`（默认 `[]`）、`angles` 与 `show_angles`（默认 `false`），两种方图的 `show_stats`（默认 `false`），江恩扇形与固定方图的 `scale_ratio`（默认 `null`），而不列出固定方图的 `size_bars`（决策 G3：边长由锚点承载，该键只在转换自有线的单锚点方图时读取）；类型化的 `drawing_kind_options` 保持上游的变体，块经由选项 JSON 到达宿主。各选项类型的默认值即上游的外观（`FibonacciToolOptions` 的 `trend_line` 与 `grid`、`GannToolOptions` 的 `time_levels` 与 `show_stats` 均默认关闭或为空），因此为某一个键创建块的补丁不会打开任何其他内容；`ProjectionAnnotationToolOptions` 只序列化与默认值不同的字段，处于默认值的块写为 `{}`。携带 `tool_options` 的模板转而替换绘图的族样式（`DrawingToolOptions::replacement_patch` 针对绘图的 `template_style`），因此应用它时，也会把它保留为默认值的那些族选项重置，而所捕获的数据（柱形态的快照）不属于样式，因此保留。持久化仅在每个可选样式字段与该种类自身的默认值不同时才写入，因此恢复后的射线保留 `extend_right`，而用户清除过它的射线仍保持清除；`labels` 与 `levels` 在与 `Drawing::new(kind)` 不同时写入，被清空的列表写为 `[]`，而上游的 `gann_fans`、`gann_arcs` 与 `level_*` 键对其种类总是写入。

## 旧版工具名与文档迁移

旧版工具名仅用于输入。自有线在采用上游目录之前写出的 28 个拼写，经由变体上的 `#[serde(alias)]` 以及 `drawings.rs` 中的 `pub(crate)` 表 `LEGACY_DRAWING_KIND_NAMES`（`DrawingKind::from_name` 会回退到该表）解析为代表同一工具的上游种类：`date_and_price_range` → `date_price_range`，十个 `fib_*` 与 `trend_based_fib_*` 名称 → `fibonacci_*` 种类，`xabcd_pattern`、`cypher_pattern`、`abcd_pattern`、`head_and_shoulders`、`triangle_pattern` 与 `three_drives_pattern` → `pattern_*` 种类，五个 `elliott_*_wave` 与 `elliott_*_combo` 名称 → `elliott_*` 种类，`arrow_mark_*` → `arrow_marker_*`，`icon` → `icon_stamp`，以及 `flat_top_bottom` → `flat_top_channel`（持久化依据第三个锚点的价格选择：不低于两个基线锚点时为平顶通道，不高于两者时为平底通道，介于两者之间时其水平线穿过基线，转为不相交通道，见下文）。每一项输出都写出目录名称（`DrawingKind::name`）。浏览器包以 `drawing_kind_alias` 与 `DRAWING_KIND_ALIASES` 镜像该表；其 wire 表 `DRAWING_KIND_TO_U8` 只包含规范行，因此 `impl.ts` 由它派生出的反向映射（`DRAWING_KIND_FROM_U8`）保持规范。

自有线写出的文档仍可加载。每次导出都会在状态层级写出 `drawing_catalog: 3`（V1、V2 与 V3；修订 3 见下文[目录修订 3](#目录修订-3)）。不带该标记的文档，只有在携带自有线写过而任何上游固定修订都未写过的内容时，才被视为自有线写出的文档：旧版或自有线的种类名称、锚点 `time`、带 `tool_options` 的样式、`drawing_price_basis`、不带 `screen_x` 的锚定文本，或缺少上游导出器会为其种类的每个绘图写出的某个字段的 B8 绘图（`lacks_upstream_b8_fields`：带层级工具的 `level_*` 标志、回归的 `regression_deviations`、图标戳的 `icon_size`、柱形态的 `bars_pattern`、艾略特波浪的 `wave_degree`；B8 之前的上游固定修订没有这些种类中的任何一个）。最后这一迹象用于识别写在非时间序列轴上的自有线文档，在这种轴上自有线不写锚点 `time`。来自上游固定修订的文档既没有该标记，也没有此类迹象，因而不经转换地加载；剩余的歧义是不带标记、其 B8 绘图全都不携带这些字段（圆弧、曲线、旋转矩形、正弦线以及其他不带层级的形状）的序列轴文档，它会不经转换地加载。恢复是原子的，因此在检查锚点数之前，一次以上游从不存储的锚点数为键的无条件预处理会转换自有线的锚点契约：`disjoint_channel` 3 → 4（镜像斜率的第二条线变为显式锚点），`gann_square_fixed` 1 → 2（由 `size_bars`、`scale_ratio` 与 `reverse` 得出的对角），`projection` 3 → 顶点与价格点，`signpost` 1 → 底部的两个锚点，`bars_pattern` 2 → 3（由框与复制的柱得出目标），`pattern_triangle` 4 → 5（E 延长 A–C 边），以及 `pattern_three_drives` 7 → 其前六个。只有自有线写出的文档才会同时转换那些锚点数在两个目录中相同的种类：`price_note` 2 → 其价格点（上游自 `12035e2` 起也存储两个锚点的价格便签，即其标签与线的终点，因此上游的两锚点价格便签以及任何剪贴板或同步载荷中的两锚点价格便签都不转换），`arc` 交换其第二与第三个锚点，`curve` 与 `double_curve` 把自有线的存储顺序（起点、终点、曲线上的点）重排为上游的存储顺序（起点、曲线上的点、终点：二次曲线 `[0, 2, 1]`，双曲线 `[0, 2, 3, 1]`），这是纯粹的重排，在每种价格比例尺上都精确，每个锚点保留其时间标识，`rotated_rectangle` 把其对称的短边中点转为一条边加一个深度手柄，`fibonacci_speed_arcs` 交换其锚点（上游以第二个锚点为弧的中心），`fibonacci_circles` 把其第二个锚点移到两锚点的中点（上游以第二个锚点为圆心、以完整距离为半径），`sine_line` 把其第一个锚点移到中点（上游的锚点是一个零点与下一个极值点，自有线的则是两个相反的极值点）。位于某个已存储锚点位置上的转换后锚点会保留该锚点的时间标识。自有线的锚定文本把其窗格比例锚点作为 ### 目录修订 3

修订 3（上游 664d347）把曲线与双曲线的内部锚点从贝塞尔控制点改为曲线上的点：二次曲线经过 t = 1/2 处的中间锚点，三次曲线经过 t = 1/3 与 2/3 处的两个内部锚点（`geometry::interpolating_curve` 由锚点推导控制点）。上游的固定修订不写目录标记，`persistence.rs` 无法把上游 664d347 写出的文档与自有线文档区分开，因此自有线跟随上游的契约，并以 `DRAWING_CATALOG_REVISION` = 3 标记新契约。恢复时：

- 修订 2 的文档（自 B8 起由自有线写出，曲线存储控制点）经 `revision_two_curve_anchors` 转换：二次曲线 `[a, c, b]` 变为 `[a, (a + 2c + b) / 4, b]`，双曲线 `[a, c1, c2, b]` 变为 `[a, (8a + 12c1 + 6c2 + b) / 27, (a + 6c1 + 12c2 + 8b) / 27, b]`，即 `interpolating_curve` 的精确逆变换。逻辑位置按仿射组合，价格同样按仿射组合，因此在普通、百分比与以 100 为基准的比例尺上绘制的曲线不变；文档不携带价格比例尺模式，恢复时窗格以普通比例尺构建，因此画在对数比例尺上的曲线改为经过这些点，形状略有不同。两端保留时间标识，转换得到的点取所存储时间在其柱处的插值（`interpolated_anchor_time`：仅当所存储锚点的时间是其逻辑位置的同一仿射函数，即锚点之间柱距均匀、误差不超过百万分之一根柱，且该点位于锚点之间时），否则保留其逻辑位置。修订 2 的信息线若没有存储 `labels`（写出器省略了等于当时默认值的四项），先获得当时的四项默认标签（价格变化、百分比变化、柱数与角度，`revision_two_info_labels`），再应用所存储的标签，无论是否带 `tool_options.line` 块，因此统计框与卡片都保持四项。
- 不带标记的自有线文档按上文的纯重排加载；不带标记也没有自有线迹象的文档（上游固定修订）与修订 3 的文档原样加载。
- 剪贴板与同步载荷不携带修订号，原样加载。同步只在同一构建的客户端之间进行，因此只有从较早构建复制的剪贴板曲线会以新的形状粘贴。
- 较早的自有线构建只检查 `drawing_catalog` 是否存在，不检查其值，因此它们把修订 3 的曲线读作控制点，绘制出不同的形状（曲线不再经过其内部锚点）；较早的构建无法再更改。

## 系列数据读取方

回归趋势线、预测与柱形态通过同一个解析器 `ChartEngine::drawing_source_series` 读取系列数据，帧、失效与捕获共用它。在绘图的窗格与价格比例尺上存活的显式 `regression_source_id` 优先，而在那里不存活的显式 id 不给出任何源，因此绘图会等待，而不是度量另一个系列。否则，源为该窗格与比例尺上按创建顺序的第一个存活的普通系列（最小的存活 `SeriesId`：标识单调，存储槽位会被复用；指标输出与自定义系列绝不符合条件，足迹图系列与 feature 系列则通过其 OHLC 投影符合条件，绘制顺序与可见性都不会改变它）。三者都通过 `ChartEngine::drawing_source_window` 读取源的规范行：即回放时钟已揭示的行，对 as-of 源则把每个规范行只读取一次，取其时间处或其后的第一个坐标轴点。

`regression_points` 取 `kinds::channels::regression_stats` 对其 `source`（`tool_options.channel.source`，默认收盘价）的记忆化拟合结果，即对位置位于两锚点之间的柱（上游的窗口：从较早锚点的 `ceil` 到较晚锚点的 `floor`）做一次无内存分配的平移求和遍历，并把每一侧放在其带符号偏移处，以总体残差偏差为单位：`regression_deviations`，除非 `upper_deviation` 或 `lower_deviation` 逐侧覆盖了该侧，被开关关闭的一侧落在中心线上（`kinds::channels::regression_band`，见[通道](#通道)）。窗口内位于不同柱上的有限源值少于两个时，不存在拟合（上游的规则），主体解析为 `DrawingBodyGeometry::RegressionWindow`：两锚点之间的虚线段，像线一样绘制与命中，因此位于未来区域、数据加载之前或位于已回退的回放时钟之后的回归线仍保持可见且可选中（自有线的占位方式）。`RegressionMemo`（`DrawingChartSettings::regression_memo`）保存每个绘图最近一次的拟合结果，以系列、合并点的位置（`time_index_generation`；as-of 源还会以每个时间点为键）、回放时钟、柱范围与源作为键，并附带它所读取的源数据代次，以及除最后一行外所有已拟合行的和。引擎会把它路由给指标的每一次系列数据变更（`update_indicators_after_change`）连同其首个变更行一并报告给该备忘缓存，因此，若某次变更使拟合最后一行之前的每一行都保持不变（对最新柱的实时替换，或追加柱），则只需用变更的行扩展该拟合，按顺序加入这些行，使结果与完整遍历逐位相同；发生在更早行的变更、未报告的变更、已移动的点或 as-of 源，则需要承担一次与锚定范围成正比的遍历。平移、缩放与指针命中测试复用该拟合，release 构建的 `perf_gate` 中的 Target N 会在 1,000,000 行的源上，对带有五条回归线的实时 tick 加帧进行计时（见[指标与绘图性能目标](../../development/performance.md#指标与绘图性能目标)）。当该备忘缓存的条目数超出绘图数量 16 项时，已删除绘图的拟合结果会被丢弃。

`forecast_result` 即 `kinds::projection_annotations::forecast_status`：当入场柱之后的某根柱至迟在目标柱处触及目标（上升目标看最高价，下降目标看最低价）时，即视为到达目标，因此入场柱本身从不计入（上游的读取方从入场柱开始读取）；当目标柱之后存在有成交的柱时，预测即告过期（上游在数据到达目标柱时即令其过期）（空白数据行，例如未来的交易时段槽位，不算柱）；并集源通过其 LOD 极值与最新柱查询（对范围为对数复杂度）作答，而 as-of 源没有规范行金字塔，它会在每次数据、坐标轴、时钟或锚点变化时对窗口内的行扫描一次，并按绘图记忆化（`forecast_memo`，与回归备忘缓存一样有界）。`capture_bars_pattern` 保留上游的快照语义（两个源锚点之间至多 512 个槽位时，每个有限行位于其相对第一行的坐标轴偏移处，因此空隙得以保留），并通过同一个窗口读取；更宽的范围按 `stride = ceil(槽位数 / 512)` 个槽位分桶，每桶合并为一根 OHLC 柱（第一个开盘价、最高价、最低价、最后一个收盘价），偏移为桶序号，因此快照仍满足上游 `offset < 512` 的校验，旧版本也能读取（决策 A9；与真实时间偏移相比压缩了时间）。每个桶按其槽位取规范行（`capture_bars_pattern_buckets`）：并集源只读取该行范围的 LOD 摘要（端点与极值行，每桶为对数复杂度），as-of 源的 LOD 汇总的是坐标轴点而非其自身的行，因此它在每次截取时逐行扫描范围内的行一次（与其回归拟合和预测读取一致），被折叠到同一坐标轴点上的行与窄范围一样合并。`invalidate_frame_series` 仅在发生变化的系列是某条回归趋势线或某个预测的源时，才重建保留的绘图层（每次数据变更会扫描一遍绘图列表；结构性的源变更会使整个场景失效），随后为绑定到该系列的分布绘图调用上游的 `invalidate_profile_drawings_using_series`。回归线的坐标键还携带其源的数据代次，因此绘图几何缓存会跟随源。

## 锚定文本与图标戳

锚定文本采用上游的屏幕模型：`screen_x` 与 `screen_y` 是窗格比例，决定它绘制在何处。`ChartEngine::anchored_text_screen_position` 从一个锚点推导它们（该锚点经绘图的窗格与价格比例尺得到的媒体 px，换算为钳制在窗格内的窗格比例），推导发生在绘图被添加时、放置提交时、其锚点被设置时，以及用于放置预览时，因此预览绘制在点击将落下的位置，而不是默认的 0.5/0.5；`drawing_px` 与运行时缓存读取该屏幕位置。自有线的窗格锚定（经 `drawing_anchor_px` 转换的窗格比例锚点、`pane_anchored` 族钩子，以及它在重新定基、磁吸、粘贴与锚点时间代码中的分支）已退役；`drawing_point_px` 作为 `drawing_to_px_for` 之上的便捷函数保留。

图标戳使用上游的图表本地注册表（`DrawingIconRegistry`，受 `MAX_DRAWING_ICONS`、`MAX_DRAWING_ICON_SIZE` 与 `MAX_DRAWING_ICON_NAME_BYTES` 限制），由 `set_drawing_icon` 填入、由 `remove_drawing_icon` 移除。上游 `12035e2` 增加了内置的实心图标集（`drawings/icons.rs`：59 个 Phosphor 2.1.1 fill 图标，MIT 许可，见仓库根目录的 NOTICE），`ChartEngine::builtin_drawing_icons()`（WebAssembly 与 TypeScript 同名）按目录顺序给出每个图标的名称与 SVG，供宿主的选择器使用。引擎把图标的轮廓按设备尺寸（四舍五入到整设备像素，最大 `MAX_ICON_RASTER_PX` = 1024）扫描转换为 RGBA，作为对齐到设备像素的 `Prim::Image` 发出，执行器 1:1 绘制，无需重采样；曲线轮廓经本仓库的展平器（`CurveGeometry::flatten`，0.1 px 容差）细分。光栅缓存（`IconRasterCache`，图表本地）以图标、设备尺寸与颜色为键，图像键从 `1 << 61` 起，与已注册图标（`1 << 62` 起）、十字光标（第 63 位）及深度热力图（`(id << 32) | rev`）的键空间分开；它同时受条目数（64）与像素字节数（`MAX_ICON_RASTER_BYTES` = 16 MiB）限制，按最近最少使用淘汰（最大的光栅也在预算之内，编译期断言）；拖动角手柄调整图标尺寸期间，每个采样的尺寸照常精确绘制但不进入缓存，释放后的那一帧只缓存最终尺寸，因此一次缩放不会用逐采样的大光栅填满缓存。覆盖率直接写入 RGBA 输出，不另外收集一份中间缓冲。箭头标记绘制同一图标集中的实心箭头，尖端落在锚点上（自有线文档也是如此；决策 R9 只恢复其文本，不恢复字形）。图标戳与箭头标记都存储 `icon_size`（8..256 CSS px，`IconBox` 手柄调整），命中区域是图标外框；`tool_options.projection_annotation.icon_size` 旧别名只对图标戳生效，取值范围相同。

图标戳的名称依次解析为：已注册的图像；同名的内置实心图标；内置图标集中没有的四个自有线 `DrawingIcon` 名称（`check`、`cross`、`triangle_up`、`triangle_down`）的自有线矢量字形；其他任何名称保留上游的彩色占位 `Rect`。`ForkGlyph::from_name` 只为这四个名称返回字形（其余五个内置名称返回 `None`，由内置图标集绘制），字形由 `kinds::projection_annotations::fork_glyph_parts` 构建，并经共享的[部件转换](#部件词汇与转换)转换。图标戳没有自有线外观（不属于 `fork_form_kind`，所有者问题 Q1 的答案 A）：字形只取决于名称，因此五个与内置图标集共有的名称（`star`、`heart`、`circle`、`square`、`diamond`）在每个图标戳上都绘制内置实心图标，无论新放置还是自有线写出的文档、剪贴板或同步载荷；恢复不添加标记，`take_legacy_flat_options` 取走旧别名（`icon`、`icon_size`）后与其他种类一样移除空的块，因此导出、补丁、粘贴与同步都不写出它。

## 各族语义

各族的语义在下面各自的块中说明。

### 线条

<!-- B8: lines — begin -->
线条族（`kinds/lines.rs`）提供转译自 KLineChart overlay 的自有线工具 `horizontal_segment`（240）、`vertical_ray`（241）、`vertical_segment`（242）与 `price_line`（243）。三个线段工具共用同一几何：前两个锚点所成的线，在第一个锚点之外按 `extend_left` 延长，在第二个锚点之外按 `extend_right` 延长，沿各自方向裁剪到窗格，未延长的端点带有端帽。它们带有目录项 `anchor_link`（`DrawingToolSpec::anchor_link`）：每个锚点共享第一个锚点的价格（`SamePrice`）或柱（`SameLogical`），该值取自最后放置或拖动的锚点。

该联动在点列表进入模型处（`Drawing::normalize_points`：构造、导入、程序化锚点以及提交一次放置）以及拖动或预览锚点期间生效，因此被锁定的工具不会离开其轴线；Shift 对它们没有可拉直之处。垂直射线默认使用 `extend_right`，使其穿过第二个锚点延伸到窗格边缘。可见的 `labels` 渲染为一个统计框，其位置由 `tool_options.line.stats_position` 决定。`price_line`（一个锚点）是一条从锚点到窗格右边缘的清晰 `hline`，外加一个位于其起点上方、显示锚点价格的部件标签；它采用水平线的 `axis_price_label` 标签，并按射线方式命中。四个线条族工具与价格通道和每个目录工具一样默认 1 px 宽；文档存储的线宽不变。

上游目录的六个线条工具（`ray`、`extended_line`、`info_line`、`trend_angle`、`cross_line` 与 `arrow_line`）没有族，由上游的转换绘制；存储的 `tool_options.line` 块（`lines::fork_presentation`）在其上游的线段与十字线分支之上叠加自有线的外观（`lines::upstream_line_parts`，经 `push_parts` 绘制、经 `parts_hit` 命中）。可见的 `labels` 改为一个由引擎格式化、作为主体命中目标的统计框（`PartContext::stats_box`，位置由 `stats_position` 决定；测量范围的统计框也由它构建，背景同为绘图描边色的 `STATS_ALPHA`，文本颜色由调用方的规则决定：线条工具用 `text_on`，测量范围沿用其 `text_color` 优先的对比规则，因此两者的像素都不变），通用标签遍历跳过这些工具。五个线段工具在上游解析出的端点之间经 `DrawingParts::capped_segment` 描边，只在没有延伸到窗格边缘的端点上绘制端帽（延伸规则只有 `geometry::segment_extension` 一处，解析器与端帽共用），箭头端把描边缩回一个描边宽度，使平头端不会从变窄的箭头中露出；端帽是主体命中目标，上游对未修剪线段的检测保留，因此命中范围只增不减。角度线再加上朝第二个锚点一侧、与线段等长的 1 CSS px 清晰虚线参考线，参考线与线段之间的 1 CSS px 圆弧（半径为线段长度的三分之一，夹在 16 到 48 CSS px 之间，按 `CURVE_TOLERANCE` 展平），以及圆弧旁折算到 [-90°, 90°]、保留两位小数的屏幕角度（不可命中）。十字线保留其上游的清晰线条，只增加统计框。每个绘图的图元顺序为：描边与端帽、参考线、圆弧、角度文字、统计框，然后是上游的 `text`。没有该块时，这些工具与上游逐图元一致：角度线绘制上游的点线水平参考线、点线圆弧与带符号的角度，信息线绘制上游的统计卡片（见[绘图](drawings.md#目录工具几何与语义)；卡片与角度的文本经同一个度量格式化器 `drawing_metric_text`，带符号，与其他自有线统计文本一致），上游角度标签超出锚点的部分（参考线、间距与 `-179.99°` 的宽度）由 `lines::upstream_decoration_extent` 计入剔除余量；自有线的箭头修剪与延伸端规则（决策 L4）也以该块为开关，因此不带该块的 `arrow_line`（包括新建的）以及带箭头端帽的射线、信息线与角度线保留上游未修剪的描边，其箭头端帽自上游 `12035e2` 起是路径工具的开放人字箭头（`path_arrow_points`，按线宽描边，折线分支同样如此），延伸端的箭头仍画在窗格边缘。带该块的文档（决策 L4）、测量范围的箭杆、四个自有线线段工具（`DrawingParts::line_cap` → `capped_segment`）以及圆弧与曲线的端帽（决策 S6，`shapes::capped_parts`）保留填充的三角形箭头（`arrow_cap_triangle`）：上游不在这些位置绘制端帽，因此没有上游外观可采用，工具栏因此显示两种箭头样式；`tool_options.line: null` 移除该块。新绘图不带该块（新的信息线保留上游的七项统计：价格变化、百分比变化、tick 数、柱数、时长、距离与角度），自有线写出的文档以及能证明出处的剪贴板与同步条目在恢复时获得该块，信息线保留自有线的五项统计（见[旧版工具名与文档迁移](#旧版工具名与文档迁移)）。

几何上（与该块无关），射线始终延伸过第二个锚点，并按 `extend_left` 穿过第一个锚点向后延伸；把射线变成线段的 `extend_right: false` 与延长线的 `extend_*` 开关不予恢复，因为上游构建写出的模板、剪贴板与同步载荷总是带着这些值为 `false` 的键，恢复它们会把上游的射线与延长线变成线段。信息线、角度线与箭头线的竖直线段按 `extend_left`/`extend_right` 延伸到窗格的上下边缘，趋势线与预测线的竖直线段保持为锚点线段。
<!-- B8: lines — end -->

### 通道

<!-- B8: channels — begin -->
通道族（`kinds/channels.rs`）提供自有线的 `price_channel`（244），即 KLineChart 的价格通道：穿过前两个锚点的基准线为中心线，其平行线穿过第三个锚点（在 px 上垂直平移，因此在每种比例尺模式下都平行，并跨越相同的柱），该平行线的镜像位于另一侧。它默认向两端延伸且不填充，填充覆盖整个区带，用 `shape::clip_polygon_to_rect` 裁剪到窗格，且仅在绘图被选中时才是主体目标。它的价格范围为 `Full`。该族的 `handles` 钩子把第三个锚点的手柄移到平行线的中点上（上游的平行、平顶、平底通道与斐波那契通道的第三个手柄同样由上游的投影放在第二条线上），因此手柄绘制（包括放置预览）、手柄命中测试与键盘微调都在那里读取它，而它仍按指针增量驱动自己的锚点。Shift 会把被拖动的基准线端点相对另一端拉直，与趋势线相同。设置 `partial_preview` 后，放置时在放置第二个锚点期间预览基准线，之后预览穿过指针的整个通道。该模块还拥有上文所述的回归读取方（`regression_stats`、`RegressionMemo`；见[系列数据读取方](#系列数据读取方)）；可选的 `tool_options.channel` 块仅存储已设置的字段。

同一模块还为上游渲染的通道与回归趋势线提供存储选项所选择的呈现，它们叠加在上游的 `Channel` 与 `Regression` 分支之上，帧与命中测试读取同一组辅助函数。`middle_line`（默认关闭，即上游的外观）在平行、平顶、平底与不相交通道上绘制一条 1 CSS px 的虚线中线（`channel_middle`，`middle_color` 为空时跟随描边颜色），它连接两条已延伸的线按方向配对的端点的中点（`paired_second`：第二条线与第一条线在 x 上反向时交换其两端），因此在两条线的端点共享柱位置时（每个平行与平顶/平底通道，以及第二条线跨越相同柱的不相交通道）它恰好位于两线中间；它在填充之后、两条线之前绘制，未选中时也是主体目标。填充同样在配对后的两条线之间形成一次 `Prim::BandFill`（按维护者的决定 C3，取代不相交通道原先沿 `first[0]`–`second[1]` 对角线拆分的两个三角形：第二条线反向时它们只覆盖四分之三的区域，而命中测试看到的是沙漏形），因此每个执行器都在交点处把相交的两条线拆成两瓣。不相交通道的四个自由端点还可能构成凹四边形（或其配对端点之间的两条边相交），此时两点带无法被每个执行器精确填充（三角形执行器的固定扇形会画到凹口里，并在两个三角形重叠处重复混合），因此 `channel_fill_ribbon` 改用该四边形经 `shape::nonzero_ribbon` 得到的精确条带作为 `BandFill` 的链；凸四边形与两线相交的情形保持两点带。选中时的填充命中使用与绘制相同的链（`ChartEngine::band_fill_hit`，即 `shape::point_in_ribbon`，仅在绘图被选中时成立）。平行与平顶/平底通道的两条线本就同向，其图元保持不变。这项修正偏离了上游的转换与上游测试 `channel_catalog_renders_shared_band_and_keeps_editable_anchors`（现在对每个通道都断言 `BandFill`），作为对 AerisTerminal 上游的提议记录，使今后的同步保持可合并。

回归趋势线的选项在 `regression_band` 中按扁平的 `regression_deviations` 解析：每一侧的带符号偏移（`upper_deviation` 或 `lower_deviation` 覆盖，否则为 `±regression_deviations`；更改扁平值时保留已覆盖的一侧，按决定 C4），`use_upper_deviation`/`use_lower_deviation` 开关（关闭的一侧既没有线，也没有区带），`source`，以及 `show_pearsons`。区带（`regression_zone`）从上侧线填充到下侧线；两侧位于中心同一侧时，它从中心填充到较远的一侧（自有线从中心向每一侧各填充一个区域）；两侧都关闭时不填充。`middle_line` 把中心线画成 `middle_color` 的 1 px 虚线，而不是上游的实线。`show_pearsons` 在起点下方绘制皮尔逊 R（`regression_parts`，经由 `push_parts`）：文字顶部位于所绘最低线起点下方 4 CSS px，终点位于起点右侧时左对齐，否则右对齐，使用绘图的标签字号与颜色，不是命中目标，其宽度经 `kinds::upstream_decoration_extent` 计入裁剪边距。`extend_left`/`extend_right` 像通道一样把三条拟合线及区带延伸到窗格边缘（`geometry.rs`），皮尔逊 R 仍位于拟合起点。选中的回归线的区带是拖动面。按维护者的决定 C1，回归趋势线的锚点只选择柱：`REGRESSION_TREND` 设置 `DrawingMovementAxis::HorizontalOnly`，主体拖动、手柄拖动、磁吸与键盘微调只改变柱位置，纯竖直的微调不记录任何历史；两个锚点的手柄由上游的投影（`anchor_handle_points`，在 `kinds::upstream_derived_handles` 中）放在未延伸的拟合线两端，因此手柄的绘制、放置预览、命中测试、键盘循环与拖动起点都在那里读取它们；没有拟合时，手柄留在占位虚线段的锚点上。只沿时间的移动偏离上游（上游的锚点可在两个轴上移动，而存在拟合时其价格不可见），作为对上游的提议记录。

### 斐波那契

<!-- B8: fibonacci — begin -->
十个斐波那契工具（回撤、扩展、通道、时间区、趋势时间、速度扇形、速度弧、圆、螺旋线与楔形）没有族，由上游的斐波那契、时间档位与斐波那契弧三个转换分支绘制；`kinds/fibonacci.rs` 读取存储的 `tool_options.fibonacci` 块，在这些分支之上叠加自有线的外观，帧与命中测试读取同一组辅助函数（`trend_line`、`draws_grid`、`label_v_align`、`phi_spiral`、`precise_rings`，以及 `frame/drawings.rs` 中的 `fibonacci_level_label`、`time_level_label` 与 `arc_level_label`）。各选项默认关闭或未设置，即上游的外观；新绘图不带该块，`Drawing::new` 保持不变（决策 F1），宿主可以在激活工具时显式传入这些选项。唯一的例外是扩展与趋势时间的 `trend_line`：不带块时它们绘制并命中上游的构造引导线（两段虚线趋势腿，位于区带填充之下，见[绘图](drawings.md#派生运行时与几何)），因此 `kinds::fibonacci::default_options(kind)` 为这两个工具给出开启的 `trend_line`：`options(drawing)` 在没有存储块时返回它，补丁新建的块也从它开始（`DrawingToolOptions::merged`），schema 描述符的默认值随之而来，因此只补丁另一个斐波那契选项时，趋势腿仍然可见。存储了块的扩展与趋势时间（每个自有线文档都有）不绘制引导线，改用下文自有线的趋势线（`draws_guides`，与 A1、R3、T1 相同的“块存在即选择”规则）：

- `trend_line`：在档位区带之后、档位线之前，以绘图自身的描边穿过锚点绘制趋势线（`push_styled_stroke`，虚线以实线短划段到达执行器）：回撤、时间区、速度弧与螺旋线连接前两个锚点，扩展与趋势时间连接三个锚点（仅在存储了块时；三点作为一条连续的描边，虚线相位连续，位于区带填充之上），圆为穿过两个锚点的 1 档直径（从第一个锚点经圆心即第二个锚点到 `2·b − a`，决策 F2，对转换后的自有线圆与自有线的 a→b 线一致），螺旋线为 1 CSS px 的虚线装饰。它是主体命中目标；开启时环形工具的屏幕框至少覆盖 1 档圆。
- `grid`（速度扇形）：每个可见档位在两个锚点构成的框内的一条水平线与一条竖直线（`FibonacciGeometry::grid_lines`，随 `level_reverse` 一并镜像），使用绘图的清晰宽度、线型与颜色，位于区带之后、射线之前，也是主体命中目标；档位超出 [0, 1] 时竖直线位于锚点之外，`DrawingBounds::for_drawing` 因此把这些档位的逻辑位置计入剔除边界。
- `full_circles`（速度弧）：经 `DrawingGeometryOptions::for_drawing` 进入解析器，扫角从 π 变为 2π，圆心、半径与标签位置不变。
- `label_v_align`（回撤、扩展、通道、时间区与趋势时间；未设置即 `top`）：`top` 是上游 `12035e2` 的位置（`top_level_label_anchor`，标签从不压在自己的线上：水平档位的价格标签中心位于线上方 4 CSS px 加 0.6 em 处、`level_label_align` 所指的位置，不需测量；倾斜档位的标签位于线段末端之外、紧挨末端，或以 `clear_label_center` 离开线段中点；末端位于窗格边缘时（江恩扇形的射线、延伸的通道）标签留在窗格内，抬到线的上方，这是本仓库对上游放置的修正，上游会把它放到窗格之外；时间标签在窗格顶部下方 14 CSS px）；`bottom` 把价格标签放到线下方 8 CSS px，把时间标签放到窗格底部上方 14 CSS px；`middle` 把时间标签放到窗格中部，把价格标签垂直居中于线，放在 `level_label_align` 所指那一端之外 6 CSS px（该端经 `extend_*` 延伸到窗格边缘时放在其内侧，`center` 居中于线段中点）。

存储的块（任意键；补丁中的空块会被丢弃）还会让速度弧、圆与楔形改用精确圆环（决策 T1）：`FibonacciArcGeometry::rings` 只细分窗格可见的那部分弧（`visible_arc`），并以能够显示的最大半径按 `CURVE_TOLERANCE`（0.1 px）经 `arc_segments` 确定弦数（至多 2,048 段），因此每个较小的圆环也在容差之内，超出窗格最远点的半径收于该处，无法到达窗格的圆环与区带不发出；圆环与区带共用同一组角度，因此成对的区带链逐点对应；只显示一部分的虚线圆环从弧起点起算的弧长上最近的虚线周期边界处开始（`Rings::stroke`），平移时虚线不随窗口边缘移动；描边经 `push_clipped_stroke` 转换。不带该块时保留上游的整圈圆环，按 `arc_segments` 以每个圆环的半径均匀细分（与真实圆相差不超过 0.1 px）。自有线写出的文档（包括带空块的楔形）都带有该块。

没有档位的螺旋线绘制黄金螺旋（决策 F3：只有空的档位列表选择它，上游此时什么也不绘制，而自有线的螺旋线正是以空列表恢复）：以第一个锚点为中心、经过第二个锚点，每四分之一圈按 φ 增长，默认在屏幕上顺时针，`tool_options.fibonacci.reverse` 时逆时针（`FibonacciArcGeometry::phi_spiral`）。它从 0.5 CSS px 的半径起，直到离开窗格为止，最多走 128 个四分之一圈，每个四分之一圈只细分其在窗格角窗口内的部分，并跳过无法到达窗格的四分之一圈，因此圆心远离窗格时工作量仍有界；虚线螺旋从内端起算的弧长上的周期边界处开始每一段，平移时虚线保持不动。它的屏幕框是整个窗格，命中测试以媒体 px 重新生成同样的曲线。

速度弧、圆与楔形的档位标签由 `arc_level_label` 放置（上游 `12035e2`）：位于该档位半径最接近竖直之处（`FibonacciArcGeometry::label_t`），沿径向以 `clear_label_center` 放在圆弧之外、从不压在描边上，居中对齐。档位标签在每个档位分支上都是主体命中目标（自有线的行为，没有选项；悬停显示移动光标，拖动移动绘图，输入控制器无需改动）：命中测试以与帧相同的放置函数得到标签，再用文本 run 命中框判定（`ChartEngine::text_run_hit`：测量出的 run 宽度、1.25 倍字号的行高，按对齐方式定位；斐波那契档位标签与形态和艾略特波浪的顶点标签使用它，见[形态与艾略特波浪](#形态与艾略特波浪)）。标签超出锚点的范围（最宽的档位标签加 6 CSS px 间距与四个字号的余量，因为价格文本随比例尺格式化器变化）经 `kinds::upstream_decoration_extent` 作为剔除余量，因此锚点刚越过窗格右边缘时，其左侧居中的标签仍会绘制，索引化命中与暴力遍历一致。绘图被选中时，每个档位分支的区带（包括与斐波那契分支共用转换的江恩扇形，不按种类限定）都是拖动面，命中检测使用与帧相同的成对链（`band_fill_hit`，即 `shape::point_in_ribbon`，与 `BandFill` 绘制的区域完全一致，螺旋区带跨圈重叠时同样如此；当前档位的线段水平时，帧把该区带绘制为从该档位到前一档位线段起点的矩形（每个方向至少 1 px），命中同样只覆盖这个矩形，因此反向速度扇形中最后一条水平射线与前一条射线之间未绘制的三角形不是拖动面）；未选中时区带让图表平移，与上游的通道相同。

逐档位的调色板线不需要新代码：上游的分支本就以每个档位自己的颜色绘制线、区带与标签，自有线文档的档位经旧版默认值获得 TradingView 调色板与区带，新绘图的档位不着色，以绘图颜色绘制（由测试固定）。斐波那契通道的 `extend_left`/`extend_right`（决策 T1）让每条档位线沿其斜率延伸到屏幕左侧或右侧的窗格边缘（`FibonacciGeometry::segment`；未延伸时 `x0`/`x1` 就是锚点自身的范围，图元不变），区带与标签随之延伸。不带这些存储选项时，每个斐波那契工具（以及江恩扇形）与上游逐图元一致：以 11 个种类 × 5 组锚点 × 8 组选项 × DPR 1、1.5 与 2 × 选中状态的帧转储比较，差异只出现在启用了延伸的斐波那契通道上。

### 叉形线与江恩

<!-- B8: pitchforks_gann — begin -->
四种叉形线（Andrews、Schiff、改良 Schiff 与内部叉形线）、叉形扇、江恩框、江恩方图、固定江恩方图与江恩扇形没有族，由上游的叉形线分支（`PitchforkGeometry`）、江恩网格分支（`GannGridGeometry`）与斐波那契分支（江恩扇形）绘制；`kinds/pitchforks_gann.rs` 读取存储的 `tool_options.gann` 块（`box_time_levels`、`angle_levels`、`shows_stats`、`ratio_point`），帧与命中测试读取同一组辅助函数。各选项默认关闭或为空，即上游的外观；新绘图不带该块。叉形线族按上游绘制其构造引导线（每个绘图都有，与块无关）：B 与 C 之间的实线叉柄底边（内部叉形线为 B 到 2C − B），中线起点不在第一个锚点上的变体另有一条从第一个锚点到中线起点的虚线腿（见[绘图](drawings.md#派生运行时与几何)）。上游 `12035e2` 的标签避让在这里沿用：叉形线的档位标签以 `clear_label_center` 离开其齿线，江恩网格把档位标签放在框的边上、扇形与圆弧所填充的网格之外（价格档位在左边缘左侧并带价格，时间档位在底边下方），与已放置的标签重叠的标签被跳过，因此小框的标签保持可读；`pitchforks_gann::upstream_decoration_extent` 把叉形线标签按 `clear_label_max_reach` 能走到的范围、江恩网格左侧与下方的边框标签计入剔除余量，因此只有标签可见的绘图仍是视口候选（叉形线此前缺少这一余量）。

- 区带命中（没有选项）：叉形线与叉形扇被选中时，帧在齿线之间绘制的每条区带都是拖动面，命中按与帧相同的链规则（`level_band_pairs`）对同一对齿线使用 `band_fill_hit`。江恩网格被选中时，除框本身外，档位超出 [0, 1] 时帧在框外绘制的档位单元格（分轴时为逐轴区带）也是拖动面，帧与命中共用同一组区带矩形（`grid_bands`：对角单元格，或分轴时横贯框宽的价格区带与纵贯框高的时间区带，按上游网格的链规则 `grid_band_pairs` 成对，隐藏档位被跳过而不打断链），帧把它们取整为 `IRect`，命中检测包含关系；扇形与圆弧的区带始终位于框内（圆弧半径不超过 1）。江恩扇形的区带由斐波那契分支处理（见[斐波那契](#斐波那契)）。未选中时区带让图表平移，帧不变。
- 叉柄中点手柄（没有选项）：叉形线与叉形扇在三个锚点手柄之后追加 `Handle(0)`，位于第二与第三个锚点（B、C）的中点（键盘第四个手柄，光标 `pointer`）；拖动它按手柄的位移（经时间吸附、磁吸与时间槽吸附）同时平移 B 与 C，A 不动，作为一次撤销。两者总是按同一个整柱位移平移（吸附后的目标相对按下时 B、C 中点的偏移，指针向零截断，键盘四舍五入），因此 B–C 的柱数不变：奇数柱宽的叉柄中点位于半柱处，分别吸附 B 与 C 会把两个 .5 的平局舍入到相反方向；指针越过一整根柱后叉柄才移动。`snap_time_to_data` 开启时，该位移会把 B 或 C 带出数据范围的采样被整体拒绝，B、C 都不动。放置预览只显示已放置锚点的手柄。在 Andrews、Schiff 与改良 Schiff 叉形线上该中点位于中线上，因此在选中的叉形线上于该处按下会拖动手柄而不是本体（与自有线及 TradingView 一致）。
- `time_levels`（江恩框）：非空时作为框的竖直（时间）档位，自枢轴角起按框宽的比例计（`level_reverse` 时自第二个锚点起），在框上方 8 CSS px 处居中标注，并先于上游的边框标签登记位置；框的 `levels` 此时只绘制水平线（标签保留上游在左边缘的位置，上游在底边下方的时间标签不绘制，否则会重复并错标这些时间档位），区带变为重叠的逐轴区带（决策 G1）：价格区带横贯框宽、时间区带纵贯框高。图元顺序为框底色、价格区带、时间区带、外框、价格档位线与标签、时间档位线与标签，然后是角度线、圆弧与统计框；命中同样只检测价格档位的水平线与时间档位的竖直线。`DrawingBounds::for_drawing` 只把时间档位计入逻辑范围，把价格档位同时计入逻辑与价格范围（价格档位的标签保留上游在左边缘的位置，超出 [0, 1] 的档位的标签位于框外），时间标签的半宽与高度计入剔除余量。为空时与上游逐图元一致（每个档位两条线，对角单元格）。
- `angles` 与 `show_angles`（江恩框）：`show_angles` 开启时，从枢轴角以 `GannGridGeometry::fan_segment` 绘制 `angles` 中的每条可见角度线（到达框的远端时间边或价格边为止），不填充、不标注，绘制在档位线之后（上游方图扇形线的顺序；自有线绘制在档位线之前），是主体命中目标。方图的 `angles` 仍是 `gann_fans` 的输入别名，方图的扇形线即 `gann_fans`。
- `show_stats`（江恩方图与固定方图）：在远角右侧 8 CSS px（方形向左生长时在左侧）垂直居中绘制统计框（先于边框标签登记位置），远角在 `level_reverse` 时取第一个锚点一侧的角。它使用共享的半透明统计框（`PartContext::stats_box`：描边颜色、alpha `STATS_ALPHA`、`text_on` 文字），经 `push_parts` 在网格之后绘制、经 `parts_hit` 命中（主体目标）。三行依次为价格范围（`format_drawing_price`；方图取两锚点的价格差，有比率的固定方图取比率对角的价格差，否则取绘制出的方形两角之间的价格差）、柱数（锚点的柱数乘以绘制出的边占锚点宽度的比例；没有宽度的方形为 0 柱）与每柱价格（四位有效数字；0 柱时省略该行）。剔除余量取三行模板的宽度加四个字号的余量，因为屏幕方形的价格范围随视口变化。
- `scale_ratio`（江恩扇形与固定方图）：`ratio_point` 在第二个锚点的柱上、自第一个锚点的价格起朝第二个锚点价格的方向偏移柱数乘以比率，得到一个派生点；`extend_drawing_render_px` 把它追加为第三个渲染点（与回归拟合点相同的机制；它像锚点一样放置，对数比例尺上的非正价格与非正锚点一样落在有限的像素上，只有非有限的像素才被跳过并回退到锚点几何），因此帧、两条命中路径、剔除与放置预览解析同一几何：扇形的 1×1 以它为终点（`resolve_drawing_geometry` 的 `GannFan` 分支），固定方图以它为远角（`gann_fixed_end`），`DrawingBounds::for_drawing` 把比率对角计入价格范围。未设置时扇形的 1×1 穿过第二个锚点，固定方图保持上游在屏幕上取较小边的正方形。
- 固定方图的对角手柄：`Handle(0)` 取代第二个锚点的手柄，位于绘制出的远角（`gann_fixed_end`）上（键盘仍为两个手柄；远角在右上或左下时光标为 `nesw-resize`，否则为 `nwse-resize`），因此远离方形的第二个锚点（例如转换得到的自有线文档）不再显示为手柄。拖动按整根柱设定边长：指针四舍五入到最近的柱，键盘每步至少按按键方向越过一根整柱（`STEP_EPSILON` 规则，边长限于 1 到 `MAX_GANN_SQUARE_BARS`，为 0 时保持按下时的方向）。有比率时边长取目标所在的柱，目标的价格设定比率（按住 Shift 保持按下时的比率），第二个锚点落在比率对角上，拖动返回的 `tool_options` 写入新的比率。没有比率时方形保持屏幕上的正方形：指针按目标离第一个锚点较大的距离、键盘按移动的那个轴确定边长，第二个锚点只取得新的柱：其价格在拖动的竖直一侧已位于新对角之外时保留，否则移到 `fixed_square_far_price`（自有线文档转换所用的同一规则）给出的远价，比例尺无法把该远价放到对角之外时取对角本身。因此时间边通常是较小的一边，普通的价格轴缩放下方形保持其整柱数；大幅缩小价格轴，或取对角本身的回退，仍可能让价格边胜出。远价规则在加法偏移会越过零时改为除法，这只保证价格为正。键盘步进不跨越整柱时（例如有比率时的竖直步进）第二个锚点的逻辑位置保持逐位不变。`snap_time_to_data` 开启时，新边长会把第二个锚点放到数据之外的采样（例如没有比率时以竖直距离为主的拖动越过最后一根柱）被整体拒绝，拖动保留上一个有效采样，与锚点拖动一致。
- 价格基准缩放：`rescale_drawing_prices` 以第一个锚点所在时间段的系数缩放江恩扇形与固定方图的 `scale_ratio`（`rescale_scale_ratio`），覆盖已提交的绘图、撤销与重做历史、待创建的绘图以及进行中拖动的 `history_tool_options`；缩放后的比率超出 `(0, MAX_SAFE_VALUE]` 时整次缩放被拒绝，什么也不改变。

不带这些存储选项时，每个叉形线与江恩工具的未选中帧与上游逐图元一致：以 9 个种类 × 6 组锚点 × 9 组选项 × DPR 1、1.5 与 2 × 选中状态（另含每个手柄的键盘微调与命中网格）的帧转储比较，差异只出现在选中时的手柄（叉形线与叉形扇多一个中点圆盘，固定方图的第二个手柄移到对角上）、选中时的命中（中点与对角手柄、已填充的叉形线区带与框外的江恩档位单元格）以及键盘手柄数与对角手柄的微调。

### 形态与艾略特波浪

<!-- B8: patterns_elliott_cycles — begin -->
六个形态（XABCD、cypher、ABCD、头肩、三角形与三驱）与五个艾略特波浪没有族，由上游的 `Polyline` 主体（`geometry.rs` 解析器、帧的折线分支及其顶点标签、折线命中分支）绘制；`kinds/patterns_elliott_cycles.rs` 解析自有线叠加在折线上的部分，帧经 `push_parts` 转换、命中测试经 `parts_hit` 检测同一组部件。`pattern_parts(ctx, PatternLayer::Under | Over, parts)` 分两层：`Under` 在折线之前绘制区域填充，`Over` 在折线与端帽之后、顶点标签之前依次绘制颈线或三角形两边、全部比率连线、全部比率框（因此连线不会压在框上）。每个部件都从任意前缀的锚点解析（缺锚点的比率、填充、颈线与两边不发出），因此放置预览直接复用它们。

- 比率（XABCD、cypher、ABCD、三驱；`tool_options.pattern.show_ratios`，默认开启，决策 P6：存储的默认值本为 `true`，自有线默认绘制比率，其文档因此从不写出该键）：每条连线是 1 CSS px 的虚线（`PartStroke::decoration`，经 `push_clipped_stroke` 以实线短划段到达执行器），比率是连线中点处保留三位小数的价格比率，带以描边颜色为底、`text_on` 或 `text_color` 文字、4×2 CSS px 内边距的框，框是主体目标。比率表沿用自有线（XABCD：XB 上 AB/XA、AC 上 BC/AB、BD 上 CD/BC、XD 上 AD/XA；cypher：AB/XA、AC 上 XC/XA、XD 上 CD/XC；ABCD：BC/AB、CD/BC；三驱：`leg_ratio(1..=4)`，在上游的六个锚点 0、1、A、2、B、3 上正好落在索引 0 到 5 之内）；参考段水平时不绘制该比率。连线与比率框是主体命中目标。
- 填充：XABCD 与 cypher 在 `fill_enabled` 时为 X-A-B 与 B-C-D 着色，头肩形态为两肩与头部相对颈线的三个三角形着色，三角形形态为两边之间的区域着色（`fill_color`，否则为描边颜色的 alpha 38）；`fill_enabled` 保持上游的默认值关闭，自有线文档经旧版默认值打开它。填充仅在绘图被选中时是主体目标（`PartContext::fills_hit`）。
- 颈线（决策 P2，每个头肩形态都绘制，没有选项）：穿过两个颈部锚点（索引 2 与 4）的直线，从它与第一段相交处到它与最后一段相交处（`shape::line_intersection`，不相交时止于颈部锚点），使用绘图自身的宽度与线型；端点位于外侧两段上，因此在锚点框内。
- 三角形两边（决策 P3）：只用前四个锚点 A、B、C、D（自有线文档迁移时把 E 放在 A–C 延长线上，因此顶点与自有线一致）；朝向由 (C+D) 与 (A+B) 的 x 比较决定，朝右时由 `extend_right`、朝左时由 `extend_left` 选择是否绘制。两边 A–C 与 B–D 在锚点前方一个图形宽度之内汇合时画到顶点，否则停在锚点上。`DrawingBounds::for_drawing` 为带标志的三角形形态把逻辑边界向两侧扩展锚点跨度、价格不设边界，而不是通用延长的无界边界，因此远处的三角形仍被时间剔除。
- 顶点标签（决策 P1，保留上游的放置）：`vertex_labels(engine, drawing, px, scale)` 给出每个标签的中心、文本与可选圆圈半径，帧、命中测试与剔除余量共用它。自上游 `12035e2` 起，每个标签以 `clear_label_center` 放在离开其顶点的各条描边之间最宽的开口里，与顶点相隔 `VERTEX_LABEL_GAP_CSS`，从不压在描边上；需避让的描边是两侧的腿，以及本仓库在该顶点绘制的比率连线（P6）、经过它的头肩颈线（P2）与三角形形态的两边（P3），带圆圈的标签按其圆圈的外接正方形避让（上游的 `"{label} ({degree})"` 文本不采用，记号见下一条）；标签是主体命中目标，命中经 `ChartEngine::text_run_hit`（测量出的 run、1.25 倍字号的行高）判定，悬停显示移动光标，拖动移动绘图。
- 艾略特记号（决策 P4）：`ElliottWaveDegree::label` 按扁平 `wave_degree` 给出 Frost–Prechter 记法（每三个级别共用一种数字：大写罗马、阿拉伯、小写罗马，并依次为圆圈、括号与无括号；字母只在阿拉伯数字的三个级别上为大写；三个千年级别以 `{}`、`[]` 与 `<>` 包围大写罗马数字），起点标签（上游的 `"0"`）不绘制。带圆圈的级别在文字之前把半径为 max(文字宽, 字号)/2 + 2 CSS px 的圆圈按 `CURVE_TOLERANCE` 展平，作为 1 CSS px 的实线折线经 `push_clipped_stroke` 发出（与自有线相同，不需要新的图元契约），并把标签上移到圆圈下缘距顶点 6 CSS px 处；圆圈内部是命中目标。
- `show_wave: false`（艾略特波浪）：折线与端帽既不绘制也不命中，标签保留为唯一的主体目标。

剔除余量由 `patterns_elliott_cycles::upstream_decoration_extent` 给出（经 `kinds::upstream_decoration_extent` 按文本键缓存）：每个顶点标签的中心最远可被 `clear_label_center` 推出的距离（`clear_label_max_reach`）加半个标签框，或其圆圈的这一距离加半径再加触摸配置的描边命中容差（圆圈内部的命中范围超出圆圈该容差），以及每个比率框半个测量宽度加内边距；比率由绘图自身的价格测量（缓存在每次变更时刷新），因此接近水平的参考段打印出任意宽的比率时，锚点刚越过窗格边缘的绘图仍会绘制并可命中，索引化命中与暴力遍历一致。不带这些选项时的上游默认帧只在获批之处改变：以 11 个种类 × 6 组锚点 × 8 组选项 × DPR 1、1.5 与 2 × 选中状态的帧转储，加上每个种类每个放置前缀的预览比较，差异只出现在谐波比率（默认开启，P6）、头肩颈线（P2）、艾略特标签（P4）、放置预览（P5），以及显式设置了 `fill_enabled`、三角形形态的 `extend_*` 或 `show_wave: false` 的情形；三角形形态在没有这些选项时逐图元不变。

### 形状

<!-- B8: shapes — begin -->
旋转矩形、椭圆、圆、三角形、圆弧、曲线、双曲线、折线与荧光笔没有族，由上游的 `Quad`、`Ellipse`、`Circle`、`Triangle`、`Arc`、`Curve` 与 `Polyline` 分支绘制（`geometry.rs` 解析器、帧分支与命中测试）；`kinds/shapes.rs` 提供它们读取的选项与辅助函数（`closed`、`capped`、`CurveStroke`、`derived_handles`、`drag_handle`、`follow_anchor_drag`、`placement_anchors`），帧与命中测试调用同一组函数。新绘图保持上游的默认值（只有旋转矩形、椭圆、圆与三角形默认填充）；自有线写出的文档经旧版默认值获得自有线的填充（圆弧与折线同样填充，决策 S1）：

- 弦区填充：`fill_enabled` 时，圆弧填充其与弦之间的圆弓形，曲线与双曲线填充曲线与其弦之间的区域，以 `fill_or_wash(51)` 的 `Prim::BandFill` 绘制在描边之下。圆弓形与二次曲线的区域是凸的（`shape::convex_ribbon`，取自感知裁剪展平的同一组点：被裁剪的部分是同一圆或曲线上两点之间的弦，因此仍是凸的）；三次曲线可能与其弦相交，按非零规则填充（`shape::nonzero_ribbon`，超出其交点与梯级上限时不填充）。帧与命中共用 `kinds::shapes::CurveStroke`（`resolve`、`run`、`chord_fill`、`capped_parts`）；该区域只在选中时是主体命中目标（`band_fill_hit`），未选中时让图表平移。共线的圆弧解析为上游的折线主体，从不填充。
- 切线延伸：`extend_left`/`extend_right` 把曲线与双曲线的起点与终点沿其切线（朝向最近的不同控制点，所有控制点都与端点重合时朝向另一端）延伸到窗格边缘（`CurveGeometry::extend`，由解析器用 `shape::extend_segment` 求得，帧与命中读取同一结果）；延伸部分是描边与主体命中目标，但不参与填充，也不带端帽。剔除沿用上游对带 `extend_*` 绘图的保守边界（整个窗格）。
- 端帽（决策 S6）：圆弧、曲线与双曲线按 `stroke_start`/`stroke_end` 在未延伸的端点绘制端帽，方向取精确的端点切线（圆弧取圆在端点处的切线，曲线取朝向最近控制点的方向）。带端帽时描边经共享的 `DrawingParts::capped_polyline` 转换（`push_parts`；箭头下的描边缩回一个描边宽度），端帽是主体命中目标（`parts_hit`），其外伸量（两个端帽半径）计入 `kinds::upstream_decoration_extent`；不带端帽时描边保持上游的单条带样式描边，逐图元不变。共线的圆弧按上游折线分支的端帽绘制。
- 闭合折线：`tool_options.shape.closed` 且有三个或更多顶点时，折线解析为 `DrawingBodyGeometry::Polygon`（`DrawingGeometryOptions::closed`）：`fill_enabled` 时按非零规则填充（`shape::nonzero_ribbon`；超过 `MAX_FILL_VERTICES`（2,048）个顶点或超出交点与梯级上限时只绘制外框，也没有内部命中目标）；外框是从第一条非零长度边的中点开始、绕行一周回到该点的一条描边（`geometry::closed_outline`），两端的平头在边中点处共线相接，每个角都是连接；不绘制端帽与顶点标签（`stroke_start`/`stroke_end` 保留，重新打开时恢复）。命中检测包括闭合边在内的每条边，填充只在选中时可命中。闭合的模板在放置时从第三个顶点起预览为闭合形状。
- 点击第一个顶点闭合（决策 S2）：放置折线时，已放置三个或更多顶点后，在第一个顶点的精确锚点半径（`HitProfile::PRECISION`）内点击，会以 `tool_options.shape.closed` 提交折线并解除工具，而不是添加顶点（`pending_close_hit`，由 `drawing_create_click` 与 `drawing_create_move` 使用；悬停其上时预览吸附到该顶点）。`path` 不闭合。Enter 与双击仍按开放折线结束；在第一个顶点上双击时，第一次点击即闭合并提交，输入控制器（`chart_input.rs`）把这对点击记为已用于放置（`SpentClick::Placement`、`Press::placement_pair`），第二次点击与双击结束序列时一样只结束放置：不打开编辑器，也不发出双击通知，这与固定点数工具在提交点击之后不同（见[绘图放置](input.md#绘图放置)）。
- 椭圆边界手柄（决策 S3）：椭圆的规格使用 `DrawingHandleMode::RectangleBounds` 与 `DrawingStraightenMode::Square`，因此它与矩形一样以其外接框的八个手柄编辑（角点保持身份，边中点只移动一条边），Shift 在放置与拖动角点时把外接框拉成正方形（即圆）；放置预览显示八个手柄。
- 旋转矩形的宽度手柄（决策 S4，仅宽度手柄）：锚点与主体仍是上游的（一条边加一个深度点，`geometry::rotated_rectangle_corners`）。上游的手柄投影把第三个手柄放在远侧边的中点（深度点本身可能位于该边所在直线上的任意位置），派生手柄（`kinds::upstream_derived_handles`）在近侧边（第一条边）的中点追加 `Handle(0)`；边长为零时不追加。两条边的锚点在拖动中按整柱吸附，宽度手柄表示一个垂直距离，保持连续。拖动 `Anchor(2)` 走通用锚点拖动：深度点按指针位移移动，远侧边按位移的法向分量移动，磁吸使远侧边穿过指针下的柱值；拖动 `Handle(0)` 把边的两个锚点沿其法向按目标的法向位移平移（`drag_handle`），远侧边不动；拖动边的某个角点（`Anchor(0)` 或 `Anchor(1)`）后，`kinds::follow_anchor_drag` 按基线的屏幕深度把深度点重新放到新边远侧的中点上，因此转动边（即使途经零长度）也保持屏幕宽度。按维护者的决定，围绕中心轴放置与编辑的对称旋转矩形不予恢复。
- 先放置两端（决策 S5）：圆弧、曲线与双曲线的点击依次为起点、终点、经过点（双曲线为 t = 1/3 与 2/3 处的两点）；`kinds::shapes::placement_anchors` 在提交（`commit_pending_drawing`）与放置预览中把点击纯粹地重排为上游的存储顺序（起点、经过点、终点）。曲线经过其锚点是上游的契约（`interpolating_curve`），因此每个内部锚点都是曲线上的普通 `Anchor(i)` 手柄，拖动锚点（包括端点）按通用锚点拖动进行，曲线随之穿过新位置；贝塞尔控制点由锚点推导，不是手柄。预览在最后一次点击之前是经过已放置点击到指针的引导折线，之后是穿过指针的曲线；手柄圆盘画在已放置的点击上，而不是重排后的锚点上。`add_drawing` 的曲线锚点依次为起点、曲线上的点、终点。曲线的语义边界计入推导出的控制点（见[绘图](drawings.md#目录工具几何与语义)）。
- 无缝外框（决策 S7）：旋转矩形与三角形的外框是从边中点开始的一条描边（`closed_outline`），不再是逐边的平头线段（宽度 2 px 及以上时角上不再出现缺口），虚线的相位沿整个外框连续；投影仍按上游逐边绘制其三角形。

不带这些选项时，上游的绘制与命中逐图元不变，按上述决策改变的除外：选中的椭圆显示八个手柄，选中的旋转矩形另有近侧宽度手柄，曲线与圆弧先放置两端，旋转矩形与三角形以一条描边绘制外框，已存储的端帽在圆弧与曲线上绘制，已存储的 `fill_enabled` 在圆弧与曲线上填充。

### 投影与标注

<!-- B8: projection_annotations — begin -->
投影与标注族（`kinds/projection_annotations.rs`）提供测量工具 `price_range`（13）、`date_range`（14）与 `date_price_range`（15）——这三个测量工具见[测量工具与瞬态测量](drawings.md#测量工具与瞬态测量)——以及自有线的 `simple_tag`（245）与 `simple_annotation`（246），即 KLineChart 的简单标签与简单标注。它设置 `owns_text` 与 `owns_labels`。简单标签是一条位于其锚点价格处、横贯窗格的虚线，带有水平线的坐标轴标签；当它带有文本时，该标签显示其 `text` 而非价格（`axis_tag_text`），因此其文本从不绘制在图表上，也不可编辑。简单标注是一根从其锚点升起的虚线杆，杆顶是一个小头部，其上方是一个带框文本标签（`DrawingParts::text_label`，因此宿主的内联编辑器可以就地编辑它）；放置它会打开编辑器（`DrawingToolSpec::requests_text_editor`），剔除余量把空文本计为一行，即其编辑器保留的插入符行。它的选项位于 `tool_options.projection_annotation` 中。该模块还拥有预测读取方（`forecast_status`、`ForecastMemo`）、旧版映射所读取的柱形态模式与图标类型（`BarsPatternMode`、`DrawingIcon`），以及内置图标集所缺四个名称的自有线字形（`ForkGlyph`、`fork_glyph_parts`：对勾与叉号为两段描边，两个三角形为单一凸多边形，因此绘制与命中测试覆盖完全相同的区域）。

上游的投影与标注种类没有族；它们的自有线外观由 `projection_annotations::fork_form` 选择：绘图带有 `tool_options.projection_annotation` 块，其种类是投影、便签、评论、价格便签、价格标签、路标、四个箭头标记或预测之一，且便签与价格便签恰好只有一个锚点（决策 A1，没有新增字段；宿主写入该块的任何键都会切换外观，写入 `null` 则恢复上游外观，因此 schema 不列出 `always_show_text`）。自有线的便签与价格便签只有一个锚点，因此带该块的两锚点便签或价格便签（例如宿主为新绘图武装了该块，得到上游的两次点击便签）仍存储该块，但绘制上游的框。新绘图没有该块，取上游的转换：便签、评论、标注框、价格便签与路标是上游 `12035e2` 的框式标注，其框、文本行与连接线由共享布局 `ChartEngine::annotation_layout`（`drawings/annotations.rs`）解析，帧（`build_annotation_prims`）、`DrawingBodyGeometry::Annotation` 的命中分支、`text_run_geometry`、剔除余量、绘制的插入符与编辑器布局都读取它；它对自有线外观返回 `None`（门控位于函数内部），因此这些路径不会彼此偏离（外观见[绘图](drawings.md#目录工具几何与语义)）。决策 R9 批准的多行文本在该布局内实现：便签、评论、标注框、价格便签与锚定文本（`DrawingKind::multiline_kind`）的文本在 `\n` 处分行，宽度取最宽一行加内边距，高度为行数 × 1.2 em 加上下内边距，每行发出一个 `Prim::Text`；便签与路标从其悬挂边向下生长，评论、标注框与价格便签从其底边向上生长，评论保持单行气泡的圆角半径。无外观块的路标与上游一样保持单行，其换行在编辑时变为空格。框的墨色规则（`ChartEngine::annotation_paint`，主题 token、存储的颜色优先、与填充对比的文本墨色、占位文本的弱化墨色）由帧与编辑器共用，因此输入的文本与绘制的文本颜色一致。标注框保留两个手柄（尾部尖端与框的左下角，目录的 `Anchors`）：上游无法单独移动框，本仓库在 B8 同步时保留了框的手柄，且编辑行为只在获批之处改变；主体拖动同时移动两者。路标的顶部是方形手柄（`OneAnchor { index: 1, square: true }`），拖动顶部时它保持在底部的柱上，形成竖直的杆。上游的价格标签是位于锚点右上方、尾部尖端落在锚点上的气泡（`price_label_layout`，尺寸取自 `price_label_bubble`）；解析器给它的文本框只是锚点本身，因此编辑器布局、文本坐标与变换、文本命中、帧插入符与可编辑性检查改由 `try_drawing_text_placement` 返回气泡的文本行（`price_label_text_start`：左对齐、不旋转），与帧绘制文本的位置一致；气泡高出锚点的部分（尾部加气泡高度）由 `projection_annotations::upstream_decoration_extent` 计入剔除余量。自有线外观全部叠加在上游的转换之上，不另起渲染器：

- 主体几何是 `geometry.rs` 中的 `DrawingBodyGeometry` 变体，由 `DrawingGeometryOptions::annotation_fork_form` 选择，并有各自的帧分支与命中分支。投影解析为 `Sector`：以顶点为圆心、顶点到目标的距离为半径，从目标一侧的水平射线到目标（至多四分之一圈，因此文本框即该象限的包围盒是精确的），按感知裁剪的方式展平；`fill_enabled` 时填充为从顶点出发的三角扇（`fill_color` 或描边颜色的 51 透明度），其上是顶点→圆弧→顶点的外框，只在选中时填充区是命中目标；半径为零时保持上游的三角形。其 `DrawingBounds` 在逻辑轴上不设界、价格保持有限（圆弧最多越过目标的时间一个半径，但不越过顶点与目标的价格），屏幕边界取扇区的精确包围盒，目录常量不变。便签解析为 `NotePin`（尖端在锚点上，头部圆心在其上方 17 CSS px、半径 7，头部有一个对比色的 2.5 px 圆点），评论与价格标签解析为 `SpeechTail`（尖端在锚点上，底边在其上方 10 CSS px、宽 10，伸入气泡 1 px），均以描边颜色填充并作为主体命中目标；价格标签不解析为上游的气泡。
- 文本只有一个所有者：无外观块的框式标注由 `build_annotation_prims` 绘制（`build_drawing_text` 对它们直接返回），其余由帧的 `build_drawing_text` 绘制。`Drawing::paints_text_block` 是静态的（多行种类 `multiline_kind`，以及自有线外观的文本所有者 `fork_text_owner`：便签、评论、价格便签、价格标签、路标与箭头标记；只取决于种类、标记与锚点数，不取决于文本或已打开的编辑器，因此宿主打开的编辑器在输入过程中不会改换所有者）。自有线外观的文本所有者（`fork_text_owner`）由 `fork_text_box` 构建一个 `PartLabel` 并经共享的部件转换绘制：便签的框位于图钉头部右侧，只在编辑、聚焦（悬停或选中，`PartContext::focused`）或 `always_show_text` 时出现；评论与价格标签的气泡左下角位于尾部底边上（价格标签以引擎格式化的价格为第一行，编辑器从第二行开始）；价格便签的框位于上游文本槽位（按 3×3 对齐距线条参考框一个文本内边距处），以价格为第一行；路标的文本牌居中立在旗形之上；箭头标记的文本位于实心箭头图标外框（`Body::IconStamp` 的中心与 `icon_size`）尾部一侧的边之外半个标签间距处，按方向对齐，不带框，取 `text_color` 或箭头颜色。框以描边颜色为背景、对比色文字与 `box_border_color` 边框。同一个 `PartLabel` 给出编辑器布局（多行）、命中测试（`drawing_body_hit` 先检测该框）、选中与悬停装饰（框外扩编辑边框宽度）以及原生插入符。
- 帧的焦点键（`RetainedFrame::last_focus_key`）记录悬停与选中的绘图中只在聚焦时绘制部件的那个（`reveals_on_focus`：没有 `always_show_text` 的自有线外观便签），焦点移入或移出时重建一次绘图层，其他悬停与选中变化仍只重新组装保留的几何。
- 投影的统计框（可见 `labels` 从顶点到目标的统计，位于目标外侧）与预测的源点圆点、源价格框和目标框（`forecast_parts`：变动及百分比、目标时间，评估后在市场涨色上显示 `Success`、在跌色上显示 `Failure`，待定时不显示）是叠加在上游投影扇区与线段分支上的部件，经 `push_parts` 绘制、`parts_hit` 命中；自有线外观的投影跳过通用标签过程，自有线外观的预测不绘制上游的结果标签。
- 剔除余量来自 `projection_annotations::upstream_decoration_extent`（经 `kinds::upstream_decoration_extent`）：图钉加框、尾部加气泡、杆与旗形加文本牌、箭头图标（`icon_size`）及其尾部之外的文本、统计框与预测框的范围，随数据变化的文本另加四个 em 的余量。无外观块的框式标注按布局的规则计入其文本的最宽一行（加 48 CSS px）与行数。
- 自有线外观的价格便签解析为横贯窗格的 `Horizontal` 线（位于其唯一锚点的价格处），其 `DrawingBounds` 在逻辑与价格两轴上都不设界；自有线外观的路标解析为 `Marker`，`MarkerGeometry::base` 记录杆的底部（锚点），`stem()` 从底部画到杆顶或第二个锚点，文本框与边界都包含底部，因此在杆脚按下也命中它。
- 每绘图的文本谓词：`Drawing::text_annotation` 对自有线外观的文本所有者保持 B8 同步前的成员（便签、评论与价格便签），其他绘图取种类的 `is_text_annotation`（上游 `12035e2` 起为便签、评论、标注框、路标与锚定文本，价格便签移出）。它决定选中后单击是否重新打开编辑器、悬停环、编辑中的按下是否保持编辑，以及清空后是否移除（`removes_when_empty`：文本工具或 `text_annotation()`）：自有线外观的价格便签清空后被移除、单击可重新打开，自有线外观的路标清空后保留、单击不重新打开；无外观块的绘图相反（上游的规则）。自有线外观的便签、评论与价格便签没有手柄（`drawing_handle_mode` 为 `None`），选中时绘制焦点框、悬停时绘制悬停环，方向键移动主体，与 B8 同步前一致；无外观块的框式标注显示其锚点手柄。

自有线外观的路标规则：锚点重合（数据谓词 `points[0] == points[1]`）的自有线外观路标立起 `SIGNPOST_POLE` = 40 CSS px 的杆，即自有线单锚点路标转换后的形状；杆按调用方比例缩放，文本放置的参考框只对该杆使用调用方比例（`text_box` 的 `scale`），因此绘制的文本段与编辑器布局在任何设备像素比下都相差上游标记自身的偏移，而其他标记的文本保持上游的单位比例参考框。其顶部手柄是位于杆顶的派生 `Handle(0)`（`derived_handles`/`drag_handle`），拖动从绘制的位置开始，取消时恢复重合的锚点；拖动或微调底部锚点（`Anchor(0)`）时，若拖动基线（`DrawingDrag::start_points`）的两个锚点重合，`follow_anchor_drag` 让顶部锚点随之移动，两个锚点保持重合，杆整体移动，与自有线的单锚点路标一致；判断只读基线而非上一个采样，因此两个锚点不同的路标在底部恰好经过顶部（时间吸附或磁吸使某个采样重合）后仍保留原来的顶部；种类余量计入该杆。锚定文本与自有线外观的框按 `\n` 堆叠为 `TextBlock`：每行从最宽一行按对齐得到的左边缘起左对齐，行距为 1.2 em，`Top` 向上、`Middle` 向两侧、`Bottom` 向下生长；单行与上游的文本段逐图元一致，多行时框、装饰、命中（主体或标签）、原生插入符与剔除余量（缓存的行数）都覆盖整个块，编辑器为多行（无外观块的框式标注的多行见上文的共享布局）。放置时，`commit_pending_drawing` 为文本为空、带该块的评论、标注框、路标与锚定文本以及自有线外观的单锚点便签写入自有线的初始文本（`starter_text`，因此也覆盖经 `drawing_tool_apply_options` 切换外观的已武装工具；两次点击放置的便签保持上游的空框）。路标的目录规格自上游 `12035e2` 起请求编辑器，因此两种外观的路标放置时都打开编辑器（`drawing_requests_text_edit` 只读规格；决策 A7 因此被上游取代，`requests_text_editor` 族函数已删除）。

## Wire id 与注册表

Wire id `0..=84` 原样沿用上游的表，上游从 85 起连续分配新种类；自有线工具占用 `u8` 空间的顶部 `240..=246`，因此上游的增长绝不会与之冲突，两者之间的空间尚未分配。别名没有 id。id 只穿越进程内的 JS/WASM 边界；文档、模板、剪贴板与同步载荷携带的是名称，因此重新编号不会破坏任何已存储的数据。一项目录标识测试断言：每个规格都具有唯一的 wire id 与名称；id `0..=84` 遵循上游的顺序，自有线工具位于 `240..=246`；`family` 恰好只为十个族工具设置；serde 名称与目录名称一致，并能经 `from_u8` 与 `from_name` 往返；每个旧版名称都解析为其种类，且自身不是目录名称。

单一列表的注册表为每个仍保留的族（lines、channels、projection_annotations）携带一个 `// B8: <family> — begin/end` 块，因此对某个族的并行工作可以以累加方式合并（`kinds/mod.rs` 中上游种类的分派函数 `upstream_decoration_extent`、`extend_upstream_schema`、`upstream_derived_handles` 与 `drag_derived_handle` 另为参与其中的 fibonacci、patterns_elliott_cycles 与 pitchforks_gann 各带一个块，projection_annotations 也在其中带有块）：

## 添加绘图族

自有线族工具的实现步骤（上游目录中的工具则改走上游的路径：`tools.rs` 中的规格、`geometry.rs` 中的主体、一个帧分支与一个命中测试）：

1. 在自有线块之后添加 `DrawingKind` 变体（serde 名称即规格名称），并在 `kinds/<family>.rs` 中添加其规格，使用 255 以下下一个空闲的 wire id 与 `family: Some(&FAMILY)`。在 `DRAWING_TOOL_SPECS` 中列出该规格及其 `spec()` 分支，并把该名称加入持久化用于识别自有线写出的文档的自有线名称中。
2. 只通过 `DrawingParts` 并使用共享辅助函数来解析几何；当纯几何具有通用性时，将其添加到 `aeris_charts_render::shape`。绝不在帧、命中测试器、执行器、WASM 或宿主中发出 `Prim`，也不得在这些位置按种类分支。用 `PartContext::point_px` 映射派生点，并按 `PartContext.scale` 比例确定描边、字形和间隙的尺寸。派生（非锚点）手柄的位置经由共享的 `handles` 钩子确定；派生手柄的拖动目前只为上游种类解析（`kinds::drag_derived_handle`，见[目录与共享钩子](#目录与共享钩子)），第一个需要拖动自身派生手柄的族须为 `DrawingFamily` 加入对应的 `drag` 钩子，并在 `drawing_drag_apply` 的 `Handle` 分支中分派到它。将绘图自身的 `text` 以 `DrawingParts::text_label` 绘制，基于 `PartContext::text_lines`，这使其无需任何宿主或 WASM 代码即可就地编辑。
3. 将族选项放入该族带 serde 默认值的块中，对列表、字符串或数字添加 `validate` 检查，并添加 `DrawingKindOptions` 投影、新类型的 `lib.rs` 再导出，以及名为 `tool_options.<block>.<field>` 的 schema 描述符。
4. 添加 TypeScript 联合类型成员与 wire id、种类选项与选项类型、演示工具栏按钮，以及 `docs/api/drawings.md` 条目；`impl.ts` 会派生其反向 wire 映射。`packages/charts/api/public-api-v1.json` 是一个生成的哈希；应重新生成它（`bun run update:api`），而不是合并它。
5. 测试：目录标识测试；族引擎测试，覆盖默认值、已激活工具的放置、DPR 为 1 和 2 以及位图比例互不相同的小数 DPR 下的帧部件、命中测试（包括在超过 20 个绘图时将索引化结果与暴力遍历对照）、带拉直与磁吸的锚点拖动与主体拖动、键盘手柄数量与微调、跨周期切换的时间标识、schema 与种类选项、原子且可撤销的选项补丁、省略默认值的持久化往返、剪贴板与同步，以及绘图自身的文本恰好只绘制一次；以及一个 Playwright 规格，覆盖已激活工具的放置、悬停与命中、选项、持久化、剪贴板与同步、工具栏，以及 WebGPU 与 Canvas2D 的一致性。`drawings/tests.rs` 中覆盖整个目录的循环测试（周期切换、索引化命中与暴力遍历对照、无数据时的退化锚点、极端缩放下与对数比例尺上的有限几何，以及剪贴板与同步往返）涵盖每个种类，因此新工具只要位于目录中就会加入这些测试。

`drawing_perf` 原生示例在其 `families` 组合中测量 B8 工具，这些工具按 wire id 从引擎目录读取，并按其目录锚点数放置每个工具，因此添加工具绝不需要编辑它。
