## 值快照

图表级数值快照由引擎根据规范 plot、当前系列类型、窗格/比例尺位置以及每个系列的格式化器一次性组装。精确逻辑模式保留每个存活系列，并将缺口或空白数据置为 null；最新模式为每个系列独立选取其自身最后一个非空白数据的逻辑索引与时间。该快照还携带同一系列上前一个非空白数据的收盘价/数值。WASM 只序列化这一有界结果，而 TypeScript 包将不透明的系列 ID 映射到现有句柄。十字光标的兼容性 `series_data` 由同一快照过滤得出，十字光标离开时暴露一个完整的最新快照，同时保留一个空的兼容映射。

## 密度查询与周期断点

内置的帧几何与系列命中测试共用一个视口密度查询。可分辨的间距使用原始行，不做改动。当每行不足一个物理像素时，该查询选择其分组符合平均像素密度的最深汇总层级，对像素桶内部使用对齐的汇总节点，并通过更低层级或原始行细化部分边界。随后，现有的按类型合并（conflation）保留折线按时间顺序的端点与收盘极值、蜡烛的首开/最高/最低/末收语义，以及直方图的最大绝对值。最终有序的 `ChartFrame` 仍是唯一的后端契约。十字光标与交易数据查找仍然是精确的原始/缓存规范查询，而不是细节层级（LOD）近似。Heikin Ashi 蜡烛图在规范 OHLC 之上使用以代次为键的引擎展示缓存：帧几何、自动缩放与蜡烛外观可以使用派生值，而 `series_data`、十字光标与交易路径继续暴露原始 OHLC。

折线连续段在周期边界处断开，而不是在空白数据处断开（空白数据行会连接，与参考实现一致）。折线、面积与基线几何（内置系列与指标线输出同样如此）在任意两个相邻已绘制行的周期键不同处开启新的连续段：带有宿主 `break_on_trading_day` 选项的系列以交易所交易日为键；VWAP（典型价格与成交额加权）与枢轴点输出以其交易日的交易时段为键，VWAP 带则以其交易时段/每周/每月重置为键，均通过 `VwapReset::period_key`，即运行时用于重置的、基于同一 `ExchangeTime` 交易日的同一个函数。键在帧构建与命中测试期间派生，因此不存储任何断开状态。指标输出以每个已绘制行的规范时间戳为键，即其运行时重置所依据的时间；宿主选项以时间轴自身的柱时间为键，在非时间的序列轴上，该时间是柱的开盘时间，而不是数据层的行键。完整重建、增量尾部更新、历史修正、保留裁剪以及合并后的行选择（键随时间单调）以相同方式断开，而交易所时间变更会使每一层失效，并使这些断点随之移动。每个连续段都输出自己的描边、颜色连续段、面积填充（保留其在未断开渐变中的那一段）、基线象限连续段以及布林带填充；仅含一个可见行的连续段会绘制参考实现的单柱水平线段，而位于窗格之外的孤立边缘邻居则不绘制任何内容（其真实线段位于屏幕之外）。在日线及更长周期的柱上，每根柱自成一个周期，因此普通描边（指标输出唯一会走到的分支）会把其连续的孤立连续段汇集为每一段区间一个 `Prim::Segments`，而不是每根柱一个两点 `Polyline`（虚线被展开为每个虚线段一对点，图案在每根柱处重新开始）；该批量会在该系列的任何其他图元之前刷出，因此图元顺序严格保持为连续段的顺序。逐点颜色、面积与基线的描边保留其两点折线。命中测试对每个连续段单独求值，因此被省略的连接线不可命中。这些断点是普通的有序图元，在每个执行器上完全一致；没有周期的系列则逐图元地保持其单连续段几何。

## 基线解析与参考线

Baseline 系列通过唯一的所有者 `ChartEngine::resolved_baseline_price` 解析其基线价格。每个消费方——系列层的象限填充与描边及可选的参考线、界面元素的实时价格线、坐标轴徽标、十字光标标记，以及公共查询 `series_baseline_price` 对原始可见范围的读取——都在同一视图与同一窗口上调用它，各自从自己保留的图层中读取：优先取固定的 `baseline_value`，否则按 `BaselineMode` 解析：`VisibleMidpoint` 为可见收盘价的中点，`CloseBeforeVisibleRange` 为第一个可见行之前最后一个有限收盘价，没有任何行先于窗口时以第一个可见的有限收盘价回退。当窗口内没有该系列的任何行（由另一系列保持窗口可见）时，中点为 `None`，而窗口之前的收盘价仍有定义，因此在两个稀疏行之间跨越窗口的连续段仍保留其象限颜色。由于输入完全相同，没有任何消费方会对某根柱位于基线哪一侧产生分歧；代表柱本身的界面元素也据此着色，见[帧契约](../rendering/frame.md#十字光标与系列界面元素)。

参考线（`baseline_line_visible`，默认关闭）是一条全窗格宽的 `HLine`，输出在象限填充与象限描边之间，且仅当该系列的几何到达窗格时输出：窗口内有一行，或一段跨越窗口、连接两个屏幕外行的连续段；构建器的行列表还携带窗格每一侧之外最近的一行，一旦系列滚出一侧，其孤立的、被裁剪的单柱几何位于窗格之外。其 y 采用价格线的取整规则，宽度采用实时价格线的规则（按垂直像素比向下取整，至少一个设备像素），颜色在系列解析时从原文 CSS 选项解析，以十字光标线令牌为回退；填充未取整的基底边缘可能与该线相差至多半个设备像素，与阈值线相同，且填充不做吸附。每个执行器都通过已有的 `HLine` 分支绘制其虚线，因此没有后端需要学习基线专属的图元。选项、模式取值与查询契约见[基线参考线与基线模式](../../api/presentation.md#基线参考线与基线模式)。

## 实时柱缓动

实时柱缓动（`live_bar_easing.rs`，按系列的 `live_bar_easing_ms` 时间常数，默认关闭）是叠加在已绘制最后一根柱上的显示覆盖：同一时间对该柱的就地替换保持规范列的权威地位，只让显示的最高/最低/收盘价向其滑动，`x += (target - x) * (1 - exp(-dt / tau))`，`dt` 每帧至多累计 100 ms；当每个通道都落在 `max(1e-9, |target| * 1e-7)` 之内，或自最后一次目标变化起经过六个时间常数时，精确落到目标上。开盘价、全新的柱、重新安装、`pop`、移动的回放截止、保留裁剪与 `reduced_motion` 都直接跳变；已绘制行保持其键时对另一行的写入（例如历史修正）不打断进行中的滑动；被 `render_before_time` 隐藏的最后一根柱从不缓动；宿主时钟回退到已记录基准之下时开启新的纪元，而不是把滑动钉在未落定状态。时间常数经由一个门读取：非有限或非正值视为关闭，并钳制到 1000 ms 上限（`MAX_LIVE_BAR_EASING_MS`），因此 Rust 宿主直接写入 `pub` 字段得到的语义与 JSON 路径相同。

状态是系列条目上的一个 `Cell`，以系列自身规范列的 `(source_row, time)` 为键，绝不通过 `DerefMut for SeriesStore` 写入（那会推进存储修订号，每帧强制完整的场景重建），因此 as-of 叠加层重复的 plot 行与回放截止都能正确键控；完整安装会在保留裁剪与时间同步之后跳变，因此同一任务中紧随安装的 Tick 以裁剪后的行集为键。帧侧读取方——K 线、柱、直方图（含被 `histogram_updown` 读取的主系列）、折线、面积、基线与标记构建器，最新值线，最新值坐标轴徽标及其宽度协商，脉冲，界面元素的柱颜色解析，该柱上的十字光标标记，以及系列命中测试——读取 `ChartEngine::display_plot`（带一行 `row_override` 的 `PlotListView`）与 `display_heikin_ashi_row`（同一 `HeikinAshiCache::project` 公式，用缓动后的原始值与前一个投影有限的规范行重新计算；空白行与部分为 NaN 的行与缓存重建一样被跨过；绝不写入缓存）。每个查询、值快照、`series_data*`、`bars_in_logical_range`、磁吸（因此十字光标水平线在滑动期间与标记相差滑动量）、交易几何、百分比基准值、`series_baseline_price` 与自动缩放都读取规范视图；在亚像素间距下，LOD 层级仍从规范极值中挑选桶代表。每次推进通过 `FrameInvalidation::series_live_display` 失效，见[帧契约](../rendering/frame.md#修订号与代次图)；时钟方法与宿主契约见[浏览器边界](../hosts/browser.md#输入订阅与动效)与 [GPUI 后端](../rendering/backends.md#gpui)，调用方式见[实时柱缓动 API](../../api/presentation.md#实时柱缓动)。

## 时间线标记带

时间线标记（`timeline_marks.rs`、`frame/timeline_geometry.rs`）是一个独立的、由引擎拥有的表面：沿主系列窗格底部的一行字形 token，与系列标记和[交易宿主叠加层](trading.md#账户成交与宿主事件)分离，从不进入 `TradingState`。宿主至多提供 4,096 个标记（`id`、unix 秒 `time`、`group`、由形状/CSS 颜色/至多两个字符的字母组成的字形、`title`）与至多 64 个不同的分组，原子地校验（超出上限触发 `ResourceLimit`；重复 id、空或过长的 id、过长的标题/标签/字母、无法解析的颜色触发 `InvalidData`，标记带保持不变），并按 `(time, group, id)` 排序一次。标记的柱槽位由引擎推导：取时间落入其跨度 `open .. open + min(step, next_open - open)` 的那根柱，其中 step 依次取已安装交易时段柱网格的间隔、未来时间投影的节奏、当前的柱间隔；落在缺口（隔夜或周末）中的时间落到下一根柱上，绝不落到缺口之前的柱上；超过最后一根柱的时间按整数个 step 投影到右侧空白区（因此只在比例尺把该空白区显示在某根可见柱旁时才绘制）；第一根柱之前或回放截止之后的时间没有槽位。序列轴（tick/成交量/range 柱）按柱的 open..close 跨度映射，不做投影。

聚类不区分分组，并在 CSS 媒体空间中确定性地进行：按槽位升序遍历 token，若某个 token 的中心位于当前簇锚点（最早的槽位）的 `token + gap`（16 + 4 CSS px）之内，则并入该簇；单一分组的簇保留该分组的字形并以计数取代字母，混合分组的簇绘制一个以图表表面色填充、以图表文字色描边的中性方块（这是对 Vela 的一处有记录的偏离，Vela 从不折叠分组），计数从一百起打印 `99+`。几何全部源于常量（16 px token、18 px 簇、位于窗格底部上方 3 px 的 24 px 标记带、10 px 字形文字），绝不依赖度量文本，因此标记带在每个执行器上像素一致；带边框的方块经 `DeviceBox` 吸附，停留提示框复用交易提示框的主题令牌。一份惰性重建的标记带布局（`lane_layout`，键为时间比例尺修订号、数据代次与回放截止、选项与投影代次、标记/隐藏分组代次、布局代次、主窗格几何以及“足够高”的判定）同时服务帧构建、悬停、光标与命中测试，由先到的调用方触发重建——悬停与光标在每次指针移动时、任何帧构建之前就会运行；命中是对可见 token 的二分查找，绝不遍历全部标记；投影 step 每次布局重建只解析一次，而悬停仲裁、光标选择与点击守卫只询问 token 是否位于指针之下（`timeline_token_under`）而不解析命中，因此指针路径不分配内存。token 在自身的方框范围内响应（16 CSS px，簇为 18，触摸配置会加宽），标记带其余部分属于窗格。

标记带在窗格高度低于四个标记带高度（96 CSS px）时隐藏，只有高于四个半（108 CSS px）时才重新显示，因此分隔条拖动不会逐帧切换它。显示且快照非空时，它在所在窗格每个自动缩放的比例尺上为数据下方预留 27 CSS px（标记带加间隙）——与哪些 token 在视野中以及隐藏分组无关，因此平移或切换分组绝不会移动比例尺；手动比例尺的窗格可以像系列标记一样与标记带重叠，而钉在底部的成交量叠加层会随之抬升。失效路径见[帧契约](../rendering/frame.md#修订号与代次图)。隐藏分组是独立于快照的集合（宿主先导入文档、后设置标记），新快照绝不裁剪它，并且是标记带唯一持久化的部分（V1、V2 与 V3 文档上的 `hidden_mark_groups`，见[持久化](persistence.md#语义文档边界)）；标记本身从不持久化。点击结果是 `ChartInputEvent::TimelineMarkActivated(seq)`，其已解析的 `TimelineMarkHit`（锚点槽位、投影标志、计数、分组、标记 id、标题、标签）保留在一个 32 项的环中，宿主无需重新推导 token；浏览器把该命中内联到 `timeline_mark_activated` 控制器事件及其 `subscribe_timeline_mark_click` 回调中，`mark:` 无障碍焦点目标——附着在 `timeline_lane_pane` 报告的窗格上，标记带隐藏时不存在——从键盘激活同一路径。丰富的点击弹层仍是宿主 UI。输入仲裁见[共享输入控制器](input.md#唯一的交互所有者)，调用契约见[时间线标记 API](../../api/presentation.md#时间线标记)。

## 高级系列与组合

官方高级系列示例是由引擎拥有的特性系列，而不是浏览器绘制回调。每个系列在保留其完整的已验证载荷的同时，还保留一份 OHLC 形态的规范投影，供共享的时间/价格比例尺与查询机制使用。分组柱、热力图、HLC 面积图、美化直方图、背景着色、堆叠面积/柱以及须线箱，在与内置几何相同的有序系列层中构建与后端无关的图元。因此，它们的官方默认值、可见范围规则、像素对齐、自动缩放语义以及源数据生命周期在浏览器与原生宿主中完全一致。可刷选 Area 刻意不是高级系列的数据类型：它是一个普通的内置 Area 系列加上由引擎拥有的临时范围样式，因此数据写入、保留策略、细节层级（LOD）、命中测试、价格比例尺归属以及所有普通 Area API 仍走规范的 Area 路径。旧版浏览器输入名称 `brushable_area` 仅是兼容性别名，并会立即规范化为 `area`。类 Area 填充共用一个设计令牌（`market.area_fill_strong_alpha` → `area_fill_faint_alpha`）：未设置的 Area 填充、两个未设置的基线半区，以及可刷选范围的默认值，都按该强度从各自的描边颜色派生渐变，在系列极值处为强、在其基底处为弱。刷选默认样式由引擎拥有（`area_brush_defaults`）；宿主只发送其覆盖的字段，以及每个范围的正/负色调。原生宿主通过一次调用 `set_brushable_area(series, Some(options))` 组合出整个交互：引擎挂接 Delta Tooltip，在每次手势之后依据其活动范围用这些默认值重新设置面积样式，在窗格双击与 Escape 时清除范围，并在该系列不再是 Area 系列时撤销该组合。

上游的线周围热力图和背景着色示例属于组合：专用引擎系列按顺序排在普通折线系列之下，而不是重复该基础系列的几何。热力图 `cell_shader` 回调是这一组中唯一的样式边界；浏览器在规范化输入时求值该回调，Rust 则随每个有界单元格保留解析后的颜色，因此每个渲染器执行的都是同一份预备好的帧。

## 官方图元与图像

具有图表语义的官方图元同样由引擎保留。系列图元跟随源跨窗格移动，并拥有其有界数据、命中状态、自动缩放贡献以及窗格/坐标轴视图；仅窗格图元保留稳定的 `PaneId`。Delta Tooltip 是非 K 线的交互：引擎拒绝将其附加到 K 线系列，并且当可转换的内置系列后来变为 K 线时，会移除已附加的 Delta Tooltip，而普通 Tooltip 仍可用于检视 K 线。普通 Tooltip 快照是结构化的柱检视器，而不是对单一数值的 DOM 猜测：Rust 解析被悬停的精确源行，并为 K 线、柱状、面积、折线、基线、直方图及其他普通呈现返回其保留的 Open/High/Low/Close。标量宿主行已经把同一个值规范化到全部四个规范列，因此标量面积/折线数据具有一致的 OHLC，而基于保留 OHLC 的面积/折线呈现即使只绘制 Close，也能检视完整的柱。可选的成交量通过时间戳对齐的 `volume_series` 显式地由宿主关联；引擎绝不猜测哪个独立直方图代表成交量。Tooltip 界面元素在浏览器边界读取图表已解析的表面色、前景色、弱化文本、边框和字体，使亮/暗主题切换不会与图表脱节。

Brushable Area 将普通 Area 系列与 Delta Tooltip 以及瞬态的 `SeriesEntry.area_brush` 呈现状态组合在一起。该辅助工具附加期间，鼠标/触控笔的主键窗格拖动归比较手势所有，而不会启动与之竞争的画布平移；价格/时间轴拖动和手动比例尺解锁仍保持普通 Area 的行为，且该辅助工具绝不会全局更改 `handle_scroll`、`handle_scale` 或图表十字光标选项。单指触摸仍可正常平移，而 Delta Tooltip 现有的双点触摸交互仍然可用。Delta Tooltip 拥有自己的比较参考线，清除/分离该交互只会丢弃瞬态刷选状态，从而恢复未被改动的 Area 渲染器。设置或清除刷选状态只会使该系列已保留的几何失效；它不会推进系列存储的修订号，因此一次拖动步骤绝不会重建布局、自动缩放、网格、坐标轴、绘图、叠加层或其他系列。浏览器可以在平台边界解码图像或求值用户提供的颜色/格式回调，但它会把有界的结果送回 Rust。引擎把图像水印存储为 RGBA8 `RasterImage` 值，并发出一个共享的 `Image` 图元；Canvas2D、WebGPU、GPUI 和原生执行器只负责上传/缓存并绘制该预备好的图像。

图像契约把每条目标边缘对齐到设备像素，并请求双线性采样；普通文本保持其独立的最近邻/旋转采样规则。Canvas2D 请求低质量平滑，因为 HTML 标准把具体的平滑算法留给浏览器决定。WebGPU 把其图像图集采样限制在图像槽位内，并上传预乘颜色。GPUI 用重复的边缘像素填充其缓存图像，以防止其固定的精灵采样器读取相邻图块。GPUI 的公开图像调用只接受字节 alpha，因此不透明度在缓存插入时被量化；缩放图像的像素门禁至多允许由此产生一个通道值的舍入差异。

## 主题来源与金融图例

金融外观在引擎中保留类型化的主题来源。网格、十字光标、看涨、看跌、影线与边框颜色要么是语义化的主题跟随色，要么是显式的自定义颜色；主题变化只会让跟随色重新令牌化。原生宿主消费并应用类型化的金融外观事务，不得通过比较已解析的 CSS 字符串来推断来源，不得为取得默认值而创建哑引擎，也不得发送空字符串颜色哨兵值来清除系列覆盖。

引擎还会从其规范值快照中投影出有序的金融图例模型。它拥有主 OHLC 的格式化与色调、原生指标输出分组、外部研究分组、可见性、窗格位置、输出标签与颜色。宿主可以描述一组有界的、真正归产品所有的系列角色（例如 Terminal 可复用的成交量系列），再将返回的类型化标识映射到其 UI 控件；不得通过遍历系列来重建由引擎拥有的分组。主行的数值来自 `FinancialLegendRequest::primary_values_series` 指定的系列，例如画在空白数据主系列之上的足迹图；它同时决定跟随主行色调的产品系列行的色调。未指定时，若图表有订单流呈现画在主系列之上（同一窗格中可见的、绑定到共享图表成交流的足迹图，即 `add_order_flow_presentation` 所建），主行读取该足迹图，因此宿主无需额外接线；否则读取主系列本身。显式指定的系列完全由宿主控制，指向不存在系列的 id 回退为主系列（系列 0）。

`histogram_updown` 成交量直方图的方向取自主系列的柱；主系列该行为空白数据时，取自同一窗格中第一个可见足迹图在该槽位的柱，并沿用成交量系列自己的 `histogram_updown_rule` 与颜色。两者都没有柱的槽位保持系列的纯色。
