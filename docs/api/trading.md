## 控件按其实际作用显示

交易控件的外观与其实际作用完全一致。此刻不能操作的控件显示普通的箭头光标，不显示悬停高亮、按下表面或提示框，在其上按下也不做任何事：图表不平移，也不开始拖动或意图。在图表发出的请求等待宿主期间，图表上的每条保护（`TP`/`SL`）订单线、每个关闭单元和每个 `TP`/`SL` 按钮都是如此；除此之外，还有不处于 working 或 partially filled 状态的订单的关闭单元，以及处于其他任何状态的保护订单的线。成交箭头继续显示其成交。关闭单元上的点击只作用于其按下开始时所在的订单或持仓，并且只在该单元于按下时可操作的情况下才生效。按住期间被宿主状态排除的拖动（订单已成交或进入待定状态，或入场单或持仓获得了该保护单）结束时不发出意图。

## 答复每一个意图

答复每一个意图，可以用 `trading().resolve_intent()`，也可以用宿主自身的状态。状态只在表明券商已处理该请求时才构成答复，它通过 `apply_snapshot()` 或该请求对象的更新或移除到达：对于取消或移动，是订单的移除、`working` 或 `partially_filled` 以外的状态（包括 `pending_cancel` 与 `pending_modify`），或超过意图中修订的 `revision`，对于移动还包括订单位于所请求的价格；对于平仓，是持仓的移除或其方向翻转；对于 `TP`/`SL` 请求，是通过 `parent_order_id`、`position_id` 或 `bracket_id` 关联到该入场单或持仓的该角色保护单，或入场单的移除、取消、拒绝或过期；对于括号单，是其某一腿处的新订单。

单纯的重新上报不构成答复：正在平仓的持仓的 P&L 跳动、仍处于意图修订的订单更新，或过时的快照。图表按上报内容显示对象，并保持每个控件惰性，因此交易者无法在第一次平仓完成之前发出第二次平仓。用 `resolve_intent(sequence, false)` 拒绝请求；拒绝会保留你重新上报的副本，而不再添加第二份。对已结算请求的后续 `resolve_intent()` 返回 `false`。光标与高亮在这些调用之后立即更新，无需指针运动。
