# 贡献指南

[文档导航](../README.md) · [架构总览](../Architecture.md) · [验证门禁](validation.md)

问题报告、可复现的测试用例、设计讨论和文档勘误，欢迎通过项目仓库提交。

Aeris Charts 采用 AGPL 与商业双许可模式。为保证 Aeris Terminal 能够同时提供这两种许可，外部代码贡献在被接受之前，需要先签署单独的贡献者协议。准备代码贡献之前，请先提交一个 issue，以便先行审阅该协议和拟议的变更。

除非已披露其来源和许可证并确认兼容，否则不得提交从其他项目复制的代码或资源。提交贡献即表示你声明自己有权依据约定的贡献条款提交该内容。

## 文档维护

- `docs/Architecture.md` 保持为简短的总览与依赖地图；具体所有权、数据流、不变量及恢复行为写入 `docs/architecture/` 对应主题，不再追加到总览末尾。
- `docs/api/` 描述使用方式与兼容性；`docs/features/` 描述领域模型；`docs/development/` 记录门禁和证据边界。基准测试操作说明仍以 `benchmarks/README.md` 为准。
- 当前实现与未来目标分开：提案留在 `plan/` 或明确标注的提案段落，不把未通过验收的行为写成已支持。
- 同一规则只维护一个详细说明，其余页面用相对链接引用。新主题同时加入文档导航或架构主题表，并提供返回入口的链接。
- 使用简体中文；路径、命令、标识符和专有名词保持原文。长段落按语义分段，示例与说明必须和当前导出、Cargo 清单、包脚本及调用路径一致。
- 移动页面后检查全仓引用，包括 Markdown 锚点、源码注释、CI 注释与工具中的路径；保留资源上限、失败/恢复条件及证据局限，不提交临时笔记、生成报告或重复文档。
- 仅文档变更检查 diff、链接/路径、架构一致性和文档规范；代码与平台行为变更按[验证门禁](validation.md)执行。
